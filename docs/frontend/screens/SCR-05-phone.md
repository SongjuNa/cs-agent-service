# 화면 명세: SCR-05 전화 상담 (임시 번호)

- 연결 요구사항: FR-050 (AC-050-1~6), FR-001(접수), FR-038(가리기), D35·D36·D37
- 기준 목업: cs-agent-mockup_v1.42.html `viewPhone`, `callLineHtml`, `callCheckHtml` (레이아웃 기준선: 위 통화 막대 → 왼쪽 대화 기록 / 오른쪽 판단·필수 정보 → 아래 통화 메모)
- 화면 정의서: 없음. 기술 명세서 §12(통화 받아쓰기 1단계)
- 사용 API: `POST /calls/transcribe`(multipart: file, customer_id, language, product_code), `POST /calls/note-draft`(utterances, language, product_code), `POST /tickets`(channel = PHONE), `GET /ref/customers?q=`

목업은 통화 중 실시간 화면이다. FR-050은 통화가 끝난 뒤 녹음을 올리는 ①단계이므로, 배치는 목업을 따르되 위 막대를 "녹음 올리기"로 바꾼다(정할 것 Q7).

## 영역

| 요소 ID | 영역 | 표시·입력 | 계약 칸 |
|---|---|---|---|
| N-05-01 | 위 막대: 녹음 올리기 | 녹음 파일, 고객 ID(필수), 고객 언어(필수), 제품 코드(선택), 접수 시각(선택, 비우면 통화 시작 시각) + [받아쓰기] | transcribe 입력 |
| N-05-02 | 위 막대: 통화 정보 | 파일 길이 "m:ss", 고객사·나라·등급 | duration_sec, `GET /ref/customers` |
| N-05-03 | 왼쪽: 받아쓴 대화 | 발화마다 말한 사람(상담원/고객), 시작 시각, 내용. 고칠 수 있음 | utterances[] (no, speaker, start_sec, end_sec, text) |
| N-05-04 | 왼쪽: 받아쓰지 못한 구간 | 대화 사이에 빨간 줄 "받아쓰지 못한 구간 m:ss–m:ss ({이유})" | gaps[] |
| N-05-05 | 오른쪽: 시스템이 판단한 것 | 고객이 말한 긴급도만. "유형·우선순위·부서는 접수 뒤 티켓 상세에서 정해집니다" | urgency |
| N-05-06 | 오른쪽: 필수 정보 | 항목마다 ✓ 찾음(값, 몇 번째 발화) / "받아쓴 글에서 찾지 못함" + "필수 정보 a/b" | provided[] (label, found, value, utterance_no, message) |
| N-05-07 | 아래: 통화 메모 초안 | 영어 메모 "[Call note] … Urgency: … Provided: …" 고칠 수 있음 + "가린 곳 n" + [메모 다시 만들기] [접수] | note_en, summary_en, mask_count |

## 화면 상태

- 빈 화면: 녹음 올리기 칸만. 아래 안내 "통화가 끝난 뒤 녹음을 올리면 AI가 받아쓰고 영어 메모 초안을 만듭니다".
- 받아쓰기 중: [받아쓰기] 꺼짐, 왼쪽에 "받아쓰기 중" 진행 표시.
- 받아쓰기 끝: 왼쪽 대화, 오른쪽 판단·필수 정보, 아래 메모 초안.
- 받아쓰지 못한 구간 있음: 그 자리 빨간 줄, 막지 않음.
- 받아쓴 내용 없음: "받아쓴 내용 없음", 메모 칸은 빈 채로 직접 쓸 수 있음.
- 메모 초안 실패: 받아쓴 글만 보이고 "메모 초안 실패" + [다시 만들기] (note_error).
- 접수 중: [접수] 꺼짐 + 진행 표시.
- 접수 끝: "{티켓 번호} 티켓으로 저장됨" + [티켓 상세 보기].
- [접수] 전에는 아무것도 저장되지 않는다는 안내를 메모 칸 옆에 둔다(D36).

## 사용자 동작 → 시스템 반응

| 동작 | 호출 API | 성공 시 | 실패 시 |
|---|---|---|---|
| 녹음·고객·언어 넣고 [받아쓰기] | `POST /calls/transcribe` | 받아쓴 대화, 빈 구간, 필수 정보 대조, 메모 초안을 한 번에 그림 | 400 "받을 수 없는 녹음 파일"(파일 칸 아래), 502 "받아쓰기 실패" + [다시 받아쓰기], 400 "개인정보 검사 오류" |
| 발화 글 고친 뒤 [메모 다시 만들기] | `POST /calls/note-draft` | 새 메모 초안과 대조 결과 | "메모 초안 실패" + [다시 만들기]. 고친 대화는 남김 |

| [티켓 상세 보기] | — | SCR-03 | — |

## 입력 검증

| 칸 | 규칙 | 문구 |
|---|---|---|
| 녹음 파일 | 필수. 형식·길이 상한은 기술 명세서 §12 | "받을 수 없는 녹음 파일" |
| 고객 ID | 필수, ref.customer에 있어야 함 | "고객 ID를 찾을 수 없음" |
| 고객 언어 | 필수, 15값 | "고객 언어를 고르세요" |
| 제품 코드 | 선택 | "제품 코드를 찾을 수 없음(모르면 비우세요)" |
| 메모(접수 때) | 필수, 2,000자 이하 | "내용을 입력하세요" |

## 수용 기준 (Given / When / Then)

- SCR-05-AC-1 (AC-050-1): Given 상담원과 고객이 번갈아 말하는 영어 시험 통화(약 3분), When [받아쓰기]를 누르면, Then 발화마다 말한 사람과 시작 시각이 보이고 "받아쓰지 못한 구간" 줄이 없다.
- SCR-05-AC-2 (AC-050-2): Given 중간 20초를 알아들을 수 없게 만든 시험 통화, When 받아쓰면, Then 그 자리에 "받아쓰지 못한 구간"이 시각과 함께 보이고 지어낸 발화가 없다.
- SCR-05-AC-3 (AC-050-3): Given 고객이 "LVB-2024-00117"을 불러 준 통화, When 메모 초안이 나오면, Then 필수 정보에 제조번호 ✓와 그 값이 보이고 메모 Provided에 같은 값이 있다.
- SCR-05-AC-4 (AC-050-4): Given 받아쓴 글에 없는 값이 든 메모 초안, When 대조 결과를 보면, Then 그 항목에 "받아쓴 글에서 찾지 못함"이 보인다.
- SCR-05-AC-5 (AC-050-6): Given 메모를 확인한 상태, When [접수]를 누르면, Then 채널 PHONE·본문 = 확인한 메모인 티켓이 생기고 "티켓으로 저장됨"이 보인다. [접수] 전에는 티켓이 없다.
- SCR-05-AC-6 (FR-050 예외 2행): Given 받아쓰기가 실패하는 상태, When [받아쓰기]를 누르면, Then "받아쓰기 실패"와 [다시 받아쓰기]가 보이고 메모 칸에 직접 써서 접수할 수 있다.

## 목업과 다른 곳

| 목업 | 명세 | 이유 |
|---|---|---|
| 통화 중 표시·시계·보류·음소거·담당 부서로 연결·통화 종료 | 녹음 올리기 막대 | 전화 장치 연동 없음. FR-050은 통화 뒤 ①단계(정할 것 Q7) |
| 실시간으로 한 줄씩 받아 적기 | 받아쓰기가 끝난 뒤 한 번에 | `POST /calls/transcribe`가 통화 전체를 한 번에 돌려줌 |
| 줄마다 한국어 번역, 상담원 말의 "통역 전달" | 넣지 않음 | 번역 보류(정할 것 Q1) |
| 판단 칸의 유형·우선순위·부서 | 긴급도만 | 그 값은 접수 뒤 처리 흐름이 정함 |
| "다음에 물어볼 것"(고객 언어 질문) | 넣지 않음 | 통화가 끝난 뒤라 쓸 곳이 없음 |
| 대기 중인 전화, 상담원 현황 탭 | 목업 화면으로 둠 | 2026-10-29 조장 답(다 묶음) |
| 상담원이 쓰는 빈 메모 칸 | AI가 쓴 영어 메모 초안을 상담원이 고침 | FR-050 처리 4·6 |
