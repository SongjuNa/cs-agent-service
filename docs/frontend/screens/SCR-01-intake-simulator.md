# 화면 명세: SCR-01 접수 시뮬레이터

- 연결 요구사항: FR-001 (AC-001-1~4), FR-003 (AC-003-1~3), D25(미등록 고객 거부), D30(팀 정답지 문의 불러오기)
- 기준 목업: cs-agent-mockup_v1.42.html `viewSim`, `runSim`, `animateSim` (레이아웃 기준선: 3단계 마법사 "문의 입력 → 자동 처리 → 완료")
- 화면 정의서: v1 SCR-01, SCR-01-P1
- 사용 API: `GET /ref/customers?q=`, `GET /ref/products`, `GET /gold/tickets/{source_ticket_id}`, `POST /tickets`, `GET /tickets/{id}`, `GET /runs/{run_id}/steps`

|---|---|---|---|
| SCR-01-01 | 머리 | "이메일·채팅·전화·포털 대신 문의를 넣습니다" + 단계 표시 3개 | — |

| N-01-03 | ③ 완료 | 고른 부서와 담당 부서가 다르면 "이 티켓은 {부서} 접수함에 들어갔습니다. 상세 화면은 부서와 상관없이 열 수 있습니다" | sub_tickets[].sub_ticket.assigned_dept |

## 화면 상태

- 빈 폼: 채널 EMAIL, 접수 시각 지금, 나머지 빈 칸.
- 불러온 폼: 입력 6칸이 채워지고 "불러옴" 칩. 제목·정답 칸은 없다(AC-003-1).
- 검증 오류: 칸 아래 빨간 글(아래 "입력 검증"), 폼 유지.
- 접수 중: [접수하고 처리 시작] 꺼짐 + 진행 표시.
- 처리 중(② 단계): 2초마다 단계 목록을 읽어 끝난 줄에 ✓, 지금 줄에 회전 표시.
- 처리 실패: 실패한 줄에 ✕와 "자동 처리 실패: {단계}" + [티켓 상세에서 다시 처리]. 티켓은 NEW로 남는다(AC-001-4).
- 완료(③ 단계): 결과 요약과 이동 버튼.

## 사용자 동작 → 시스템 반응

| 동작 | 호출 API | 성공 시 | 실패 시 |

| [다른 문의 접수] / [지우기] | — | 빈 폼으로 | — |

## 입력 검증

API 오류 문구(backend/app/db/store.py)를 칸 아래에 그대로 쓴다.

| 칸 | 규칙 | 문구 |
|---|---|---|
| 채널 | 필수, 5값 | "채널을 고르세요" |
| 고객 ID | 필수, ref.customer에 있어야 함(D25) | "고객 ID를 찾을 수 없음" |
| 제품 코드 | 선택, 있으면 23종 중 하나 | "제품 코드를 찾을 수 없음(모르면 비우세요)" |
| 고객 언어 | 필수, 15값 | "고객 언어를 고르세요" |
| 본문 | 필수, 1~2,000자, 공백만이면 거부 | "내용을 입력하세요" |
| 접수 시각 | 선택, 기본 지금, 미래 거부 | "접수 시각은 미래일 수 없음" |

## 수용 기준 (Given / When / Then)

- SCR-01-AC-1 (AC-003-1): Given 빈 폼, When CSV1-000017을 불러오면, Then channel=PHONE, customer_id=CUST-0350, product_code=ACB-AS-2000, language=en, 본문이 채워지고, 접수 시각은 원본(2025-10-02 09:45:43)이 아닌 지금이다(FR-003 v1.5.2).
- SCR-01-AC-2 (AC-001-2): Given 고객 ID에 CUST-9999, When [접수하고 처리 시작]을 누르면, Then 고객 ID 칸 아래 "고객 ID를 찾을 수 없음"이 보이고 ② 단계로 넘어가지 않는다.
- SCR-01-AC-3 (AC-001-1): Given 유효한 입력, When 접수하면, Then ② 단계 진행 표시가 보이고 처리가 끝나면 ③ 단계에 티켓 번호와 담당 부서가 보인다.
- SCR-01-AC-4 (AC-001-4): Given 언어 모델 호출이 실패하는 상태, When 접수하면, Then ② 단계에 "자동 처리 실패"와 [티켓 상세에서 다시 처리]가 보인다.
- SCR-01-AC-5: Given CSV1-000008(복합)을 불러와 접수, When ③ 단계를 보면, Then 문의 2개(FW_UPDATE, MANUAL)가 각각 유형·우선순위와 함께 보인다.
- SCR-01-AC-6: Given 본문이 공백뿐, When 접수하면, Then "내용을 입력하세요"가 보인다.
