# 화면 명세: SCR-12 자동 처리 규칙

- 연결: 최신 목업(Frontend 폴더) `#/admin/auto` "자동 처리 규칙". 변경 `add-auto-send`(규칙 3·D32 변경, 팀 합의 2026-10-31). 요구사항 번호는 아직 없음(임시 FR-초안-09)
- 사용 API: `GET /auto-rules`, `PUT /auto-rules`(머리 `X-Agent-Id`)

## 영역

| 요소 ID | 영역 | 표시 | 계약 칸 |
|---|---|---|---|
| SCR-12-S | 자동 발송 스위치 | "검증 AI 자동 발송" 설명, 켜짐/꺼짐 스위치, "지금까지 자동 발송 n건(사후 검수 전 n건) · 전체 n건 중 n%", **"이 시스템은 실제 메일을 보내지 않습니다. 실제 메일을 연동하기 전에 먼저 이 스위치를 끄세요" 안내** | enabled, stats |
| SCR-12-C | 문의 유형별 | 자동 대상 유형(매뉴얼·기술 사양·펌웨어·인증·규격)은 켜고 끄는 상자, **항상 사람이 확인하는 유형 6종(고장·불량, 설치, 반품, 보증, 견적, 주문·납기)은 잠금("항상 사람 확인")** | cats, auto_cats, always_human |
| SCR-12-H | 채널별 | 채널(메일·웹 양식·전화·채팅·포털)마다 켜고 끄는 상자 | channels |
| SCR-12-K | 자동 발송 조건 | 고정 기준 목록: 우선순위 P3·P4 / 긴급도 일반 / 단일 문의 / 필수 정보 있음 / 근거 문서 있음 / 답변 초안이 있고 발송 전 확인할 것 없음 / 검증 통과. "하나라도 걸리면 상담원이 확인" | — |
| 머리 | [기본값으로] | 목업 기본값(켜짐, 매뉴얼·기술 사양·펌웨어 켜짐, 인증·규격 꺼짐, 전화 꺼짐)으로 저장 | PUT |

## 화면 상태

- 상담원을 고르지 않으면 안내 띠("상단에서 상담원을 고르면 설정을 바꿀 수 있습니다")를 보이고 스위치·상자·[기본값으로]를 끈다. 읽는 것은 된다.
- 스위치가 꺼지면 유형·채널 상자를 끈다.
- 누른 값은 화면에 바로 보이고 서버에 저장한다. 저장이 실패하면 안내 띠를 보이고 서버 값으로 돌아간다. 연달아 눌러도 마지막 값이 남는다.
- 읽기 실패: "불러오지 못함. 새로고침".

## 수용 기준

- SCR-12-AC-1: Given 상담원을 고른 상태, When `/admin/auto`를 열면, Then 스위치가 서버의 켜짐 여부와 같고 "지금까지 자동 발송"·"사후 검수 전" 숫자가 서버 통계와 같으며, 고위험 유형 6종이 잠겨 있고, 고정 조건 목록과 "실제 메일을 보내지 않습니다" 안내가 보이고, 왼쪽 메뉴의 "자동 처리 규칙"이 현재 화면으로 표시된다.
- SCR-12-AC-2: Given 같은 화면, When 스위치를 끄면 유형 상자가 꺼지고, 켠 뒤 "매뉴얼"을 끄면 서버에 저장되며, [기본값으로]를 누르면 서버 설정이 기본값(켜짐, 매뉴얼 켜짐, 인증·규격 꺼짐, 전화 꺼짐)이 된다.
- SCR-12-AC-3: Given 상담원을 고르지 않은 상태, When 열면, Then 안내 띠가 보이고 스위치와 [기본값으로]가 꺼져 있다.
- SCR-12-AC-4: Given 접수함, When [자동 처리]를 보면, Then 숫자가 서버 `counts.auto`와 같고, 누르면 `auto=true`로 거른 목록(닫힌 문의 포함)이 열리며 줄마다 "AI 자동 발송 · 검수 대기/검수 완료" 표시가 있다. 다시 누르면 필터가 풀린다.
- SCR-12-AC-5: Given 운영 대시보드, When 열면, Then "AI 자동 처리율" 카드와 "AI와 사람 처리 비중" 막대가 서버 `auto`(자동 발송·사후 검수·사람 발송) 집계와 같다.

## 화면 연동 (변경 add-auto-send-views)

- 접수함: 줄에 `auto_state`(NONE·PENDING·REVIEWED). 사후 검수 전(PENDING)은 문의가 닫혔어도 "내 차례"(`next_action=REVIEW_AUTO`, 문구 "자동 발송 사후 검수")로 기본 목록에 남고, 검수하면 DONE이 되어 빠진다. [자동 처리] 단추(`auto=true`)는 검수 끝난 것까지 닫힌 문의도 보여 준다.
- 문의 상세: 지금 할 일 띠에 "사후 검수 — AI가 사람 승인 없이 보낸 답변이 맞는지 확인하세요"와 [사후 검수 완료](한 번만, 누른 상담원 이름 기록). 발송 카드에 "AI 자동 발송" 표시.
- 나의 업무 현황: 내 담당 문의 중 최근 7일 자동 발송 건수와 검수 대기 건수 카드(둘 다 0이면 숨김), [확인하기]는 `/inbox?auto=true`.
- 운영 대시보드: "AI 자동 처리율" 카드(자동 발송 / 보낸 최종 답변)와 "AI와 사람 처리 비중" 막대. 숫자는 서버가 센 값을 그대로 보인다.
- 자동 발송 건이 없는 환경에서도 성립하는 값(서버 숫자와 화면 숫자의 일치)만 e2e로 본다. 사후 검수 버튼과 차례 변화는 서버 시험(`test_auto_send_views.py`)이 본다.

## 안전장치 (변경 add-auto-send 설계 참조)

- 고위험 유형·P1·P2·안전·설비 정지·복합 문의·막는 정보 누락·근거 없음은 설정으로 풀 수 없다(서버가 400으로 거부).
- 자동 발송은 상담원 [승인하고 발송]이 보는 확인(`send_issues`)이 비어 있고 검증을 통과한 초안만 보낸다.
- 서버 기본값은 환경 변수 `AUTO_SEND_DEFAULT`(기본 true, 시험은 false). 실제 메일을 연동하기 전에는 false로 둔다.
