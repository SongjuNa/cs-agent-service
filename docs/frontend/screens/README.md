## 읽는 법

- 목업은 **배치와 모양**의 기준이다. **값, 규칙, 문구, 동작**은 기준 문서와 API를 따른다.
- 둘이 다르면 명세는 기준 문서 쪽으로 쓰고, 각 명세 끝 "목업과 다른 곳"에 적었다. 정할 것은 [정할 것 모음](#정할-것-모음)에 모았다(CLAUDE.md "문서끼리 다르면 사람에게 묻는다").
- 요소 ID는 화면 정의서의 번호를 그대로 쓴다(예: SCR-03-C-07). 새로 생긴 요소는 `N-`을 붙였다.
- 수용 기준 번호는 `SCR-02-AC-1`처럼 화면 번호를 붙이고, 같은 내용의 FR 완료 기준(AC-029-1 등)을 괄호에 적었다. 5단계 화면 시험은 이 번호를 그대로 쓴다.

### 명세를 쓰지 않은 목업 화면

| 목업 화면 | 이유 | 결정 |
|---|---|---|
| 로그인, 설정(viewLogin, viewPrefs) | 로그인 없음(D23). 설정은 팀 결정과 부딪힘 | 목업 화면으로 둔다 |
| 공지사항, 시스템 알림(viewNotice, viewSysNotice) | 새 표가 필요함 | 목업 데이터로 둔다(2026-10-29 조장 답) |
| 챗봇 관리, 고객포털, 전화 › 상담원 현황(viewChatbot, showPortal, viewAgents) | 우리 시스템 밖 | 목업 화면으로 둔다(2026-10-29 조장 답) |
| 운영 대시보드(viewOps, SCR-06) | 어떤 화면을 보여 줄지 아직 정하지 않음 | 목업 화면으로 둔다(2026-10-29 조장 결정). SCR-06 명세와 백엔드 제안(add-ops-dashboard, add-dashboard-tabs)은 보류 |
| 지식 관리의 고치기·올리기(표 올리기, 색인 다시 만들기) | 규칙표 관리 화면은 범위 밖(2026-10-23 조장 결정) | 보기만 SCR-08에 |

## 공통 규칙 (모든 화면)

화면 정의서 v1 0-3·0-4절을 그대로 따른다. 화면 명세마다 되풀이하지 않는다.

| 항목 | 규칙 | 근거 |
|---|---|---|
| 상담원 식별 | 로그인 없음. 상단에서 고른 상담원 ID·부서를 모든 요청 머리 `X-Agent-Id`, `X-Agent-Dept`에 싣고 브라우저에 기억 | D23, D33, 화면 정의서 v1 0-4 |
| 기준 시각 | 표시는 "2026-04-20 17:55 UTC". 조회는 `as_of`(실제 시각 / 스냅샷 2026-09-30 23:59 UTC) | 화면 정의서 v1 0-4 |
| 로딩 | 표는 스켈레톤 행, 카드는 회색 자리 | 화면 정의서 v1 SCR-02 ⑥ |
| 읽기 실패 | 이전 값을 흐리게 두고 "{대상}을 불러오지 못함. 새로고침" 띠 | 화면 정의서 v1 0-4 |
| 쓰기 실패 | 서버가 준 `detail` 문구를 그대로 보이고 화면 값은 바꾸지 않음. 409 충돌은 P8 "다른 사용자가 변경함. 새로고침" | 화면 정의서 v1 SCR-03-P8, backend 오류 문구 |
| 자동 갱신 | 접수함·업무 현황·대시보드 5분마다, 티켓 상세는 처리 중일 때만 2초마다 | 화면 정의서 v1 0-4, 기술 명세서 §2-4 |
| 발송 관문 | 고객에게 가는 글은 모두 [승인·발송] → P7을 지난다. 예외는 126h 리마인드뿐 | CLAUDE.md 규칙 3, D32 |
| 남은 시간 | 소수 첫째 자리 "36.2h", 넘으면 "−12.5h", 대기 중 "멈춤", SLA 없음 "SLA 미정" | FR-029 출력, CP-2 |
| 페이지 | 목록 API는 한 쪽 50건 | FR-029 처리 7 |
| 신뢰도 숫자 | 화면에 확신도 숫자를 쓰지 않고 "확신 낮음" 칩만 | 화면 정의서 v1 CP-8(디자인 가이드 §7.4) |

## 정할 것 모음

각 명세의 "목업과 다른 곳"에서 조장 답이 필요한 것만 모았다. 답이 오기 전에는 오른쪽 "명세의 기본값"으로 쓴다.

| # | 화면 | 질문 | 명세의 기본값 |
|---|---|---|---|
| Q1 | SCR-02·03·05 | 한국어 번역(접수함 제목, 고객 원문 번역, 통화 줄 번역)을 넣을까 | 넣지 않음. FR-030 "번역 토글은 여유 시 항목" |
| Q2 | SCR-04 | 목업의 처리 실적 차트·최근 처리 문의 탭을 넣을까 | 넣지 않음. FR-047 처리 1~5만 |
| Q3 | SCR-04 | 목업에 없는 "기한 위험·위반 목록"을 둘까 | 둠. FR-047 처리 2가 정한 영역 |
| Q4 | SCR-03 | 목업의 확신도 숫자(0.93)를 보일까 | 보이지 않음. "확신 낮음" 칩만(CP-8) |
| Q5 | SCR-03 | 발송 확인 창의 "의견 (필수)" 칸을 둘까 | 두지 않음. API(SendIn)에 칸이 없고 FR-031은 override_check 기록만 |
| Q6 | SCR-03 | 펌웨어 조회 결과를 판단 탭에 보일까 | 보임. 백엔드가 상세에 넘기도록 작게 바꿈 |
| Q7 | SCR-05 | 전화 상담을 통화 뒤 흐름으로 다시 그릴까 | 다시 그림. FR-050 ①단계(녹음 올리기 → 받아쓴 글 → 메모 초안 → 접수) |
| Q8 | SCR-09 | 사례 "제외/다시 사용" 단추와 참고 횟수를 둘까 | 두지 않음. 새로 쓰는 데이터가 필요 |
| Q9 | SCR-06 | 목업의 고정 KPI(기한 준수율 91.4% 등)와 "부서별 통계" 탭 | 고정 KPI는 뺌. 부서별은 개요의 부서별 미해결 표로 대신 |
| Q10 | SCR-06 → SCR-02 | 대시보드 제품·고객 행을 누르면 접수함을 그 제품·고객으로 거르는데, 접수함 API에 그 필터가 없다. 백엔드에 product_code·customer_id 필터를 더할까 | 더하지 않고, 행 클릭은 고객이면 고객 상세(SCR-07), 제품이면 제품 상세(SCR-08)로 보냄 |
| Q11 | SCR-03 | 처음 여는 탭: 목업은 "고객이 보낸 것", 화면 정의서 v2는 "보낼 것" | "보낼 것"(화면 정의서 v2) |
