# 화면 명세: SCR-06 운영 대시보드

- 연결: FR-034(전 부서 위험 현황), 최신 목업(Frontend 폴더) `#/admin` "운영 현황". 변경 `add-ops-overview`(서버 집계 API와 이 화면), `add-dashboard-history`(해결·종료 이력 적재)
- **팀 합의(2026-10-31): 목업이 최신 기준.** 이전 명세(2026-10-29, 위험 목록 + 부서별 표 + SLA 상태별 건수 + AI·제품·고객 탭, 보류)와 그에 딸린 보류 제안 `add-ops-dashboard`·`add-dashboard-tabs`는 이 명세로 **대체**한다(구현하지 않음).
- 사용 API: `GET /dashboard/summary?days=&as_of=`(읽기만)

## 화면 상태

- 로딩: 회색 자리. 읽기 실패: 이전 값을 흐리게 두고 "불러오지 못함. 새로고침" 띠(첫 읽기 실패면 띠만).
- 자동 갱신: 5분마다. 기간을 바꾸면 그 기간으로 다시 읽는다.
- 수치 정의(서버): 기한 초과 = 해제되지 않은 경고에 `*_BREACHED`가 하나라도, 임박 = `*_AT_RISK`만(접수함과 같은 정의). 이관 지연 = 이관한 지 168시간이 지난 건. 기한 충족은 **접수일이 기간 안인** 문의 기준이고 1차 응답은 MET·BREACHED만 센다.

## 수용 기준

- SCR-06-AC-1: Given 스냅샷, When 운영 대시보드를 열면, Then 숫자 카드(미해결·기한 위반·1차 응답 충족률)와 한 줄 요약이 서버 `/dashboard/summary` 값과 같고 일별 접수 그래프가 보인다.
- SCR-06-AC-2: Given 같은 화면, When 기간을 90일로 바꾸면, Then 서버에 `days=90`으로 다시 묻고 카드 설명이 "최근 90일"로 바뀐다.
- SCR-06-AC-3: Given 같은 화면, When "기한 위반" 카드를 누르면, Then 문의 배정 관리가 `kind=breach`로 열린다.
- SCR-06-AC-4: Given 같은 화면, When 부서 막대를 누르면, Then 문의 배정 관리가 그 부서(`dept=`)로 열린다.
- SCR-06-AC-5: Given 읽기 요청이 실패하는 상태, When 열면, Then "불러오지 못함. 새로고침"이 보이고 [새로고침]을 누르면 다시 읽는다.
