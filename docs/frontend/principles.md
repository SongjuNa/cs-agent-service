# 프론트엔드 원칙 (프론트 헌법)

화면 코드를 쓰는 사람과 AI 도구가 모두 따르는 규칙이다. 저장소 `CLAUDE.md`의 규칙 8개가 먼저이고, 이 문서는 그것을 화면 쪽으로 넓힌다(근거: 조장 3단계 지시 2026-10-29 "백엔드 SDD에서 쓰던 원칙 문서를 프론트용으로 확장").

근거 표기는 `openspec/config.yaml` design 규칙과 같다. 문장 끝 `(근거: …)`는 기준 문서·조장 결정·조장 지시에서 온 것이다. `구현 선택`은 기준 문서가 정하지 않아 구현하면서 고른 것이다. `제안 — 조장 확인`은 아직 정해지지 않은 것이며, 확인되기 전에는 바꿔도 된다.

| 줄임 | 문서 |
|---|---|
| 3단계 지시 | 조장 메시지 2026-10-29 "3단계: 공통 기반을 먼저 만든다" |

| 화면 명세 | `docs/frontend/screens/` SCR-00~SCR-09 (2단계 결과) |

## 1. 작업 순서

1. 화면 하나를 만들기 전에 그 화면의 화면 명세(`docs/frontend/screens/SCR-xx-*.md`)를 읽는다. 명세에 없는 동작은 만들지 않는다(근거: CLAUDE.md "여기에 없는 기능은 만들지 않는다", 조장 2단계 지시).
2. 공통 컴포넌트(`src/ui/`)와 디자인 토큰(`src/styles/tokens.css`)을 먼저 쓰고, 없을 때만 새로 만든다(근거: 3단계 지시, 기술 §8-2 "공통 부품을 먼저 만든다").
3. 화면 명세의 수용 기준(SCR-xx-AC-n) 하나마다 테스트 하나를 만든다(근거: CLAUDE.md 규칙 7, 조장 2단계 지시 "AC가 5단계 테스트가 된다").
4. 기준 문서끼리, 또는 문서와 목업이 다르면 고치지 말고 묻는다(근거: CLAUDE.md "문서와 코드, 또는 문서끼리 값·이름이 다르면 사람에게 묻는다").

## 2. 폴더 구조

목표 구조는 아래와 같다(근거: 3단계 지시 "폴더 구조". 폴더 이름과 나눔은 `제안 — 조장 확인`).

```
frontend/src/
  main.tsx            앱 시작. QueryClientProvider와 토큰 CSS를 여기서 붙인다
  App.tsx             틀(A안 사이드바 + 머리 막대)과 주소 나누기 (근거: 정의서 v2 0-7)
  queryClient.ts      서버 데이터 기본 설정(§4)
  api.ts              서버 호출 함수, ApiError, 상담원 머리값 (근거: 기술 §8-1 X-Agent-Id·X-Agent-Dept)
  api.gen.ts          openapi.json에서 만든 타입. 손으로 고치지 않는다 (npm run gen:api)
  styles/tokens.css   디자인 토큰. 색·글꼴·간격은 여기서만 정한다(§3)
  ui/                 여러 화면이 같이 쓰는 컴포넌트(§5). 화면 지식(API·주소)을 모른다
  features/<화면>/    화면 하나의 코드. 예 features/inbox, features/ticket-detail   ← 4단계에서 옮김
```

- 지금(3단계)은 기존 화면 파일(InboxPage.tsx, TicketDetailPage.tsx 등)이 `src/` 바로 아래에 있다. 4단계에서 화면을 하나씩 `features/`로 옮기면서 `src/ui/`의 컴포넌트로 바꾼다. 옮기기 전까지 기존 `styles.css`와 같은 이름의 중복 컴포넌트(DetailTabs의 StatusBadge, MyWorkPage의 Status, Popups의 Modal)는 그대로 둔다 (`구현 선택`: 3단계에서 화면을 건드리지 않기 위해).
- `ui/`는 `features/`를 import하지 않는다. `features/<A>`는 `features/<B>`를 import하지 않고, 같이 쓸 것은 `ui/`나 `api.ts`로 올린다 (`제안 — 조장 확인`).
- 화면 코드는 공통 컴포넌트를 `src/ui/index.ts`에서만 가져온다(`import { Button } from "../ui"`) (`구현 선택`).

## 3. 디자인 토큰

- 색·글꼴·글자 크기·간격·둥글기·높이·그림자는 `src/styles/tokens.css`의 CSS 변수로만 쓴다. 컴포넌트 CSS와 화면 코드에 `#색값`이나 px 숫자를 직접 쓰지 않는다(근거: 3단계 지시 "디자인을 바꿀 때 토큰만 고치면 전체에 반영"). 예외: 1px 선 굵기, 아이콘 글자 크기처럼 토큰으로 둘 뜻이 없는 값 (`구현 선택`).
- 토큰은 두 층이다. 1층 `--c-*`는 LS CI 원색으로 tokens.css 안에서만 쓴다. 2층 `--color-*`는 뜻 이름(bg, surface, fg, brand, neg, crit, pos, info, neu…)이고 컴포넌트는 2층만 쓴다 (`구현 선택`: 테마 바꾸기를 2층 값 교체로 끝내기 위해, 근거: 3단계 지시 "테마 전환이 쉬워짐").
- 어두운 테마는 `<html data-theme="dark">` 또는 운영체제 설정(prefers-color-scheme)으로 켠다. `data-theme="light"`면 운영체제가 어두워도 밝게 보인다 (`구현 선택`). 화면에 테마 전환 버튼을 둘지는 화면 명세에 없으므로 두지 않는다.
- 상태 색은 정의서 v2 0-5와 B-3의 CI 색을 따른다. 빨강은 글자·테두리에만 쓰고 빨강 바탕에 흰 글씨는 쓰지 않는다(근거: 정의서 v2 0-5). 목업 v1.42의 상태 색과 다르며 어느 쪽으로 할지 조장 확인 중이다.
- 크기·간격·모양(카드 20px 둥글기, 알약 버튼, 버튼 높이 36·30, 칩 22, 간격 2·4·6·8·10·12·14·16·20·24)은 목업 v1.42에서 여러 번 나오는 값을 옮겼다(근거: 3단계 지시 "목업 전체에서 반복되는 색상·글꼴·간격을 디자인 토큰으로 추출").

## 4. 상태 관리

| 무엇 | 어디에 둔다 | 근거 |
|---|---|---|
| 서버에서 온 데이터(목록, 문의 상세, 업무 현황, 참고 표) | TanStack Query (`useQuery`) | 3단계 지시 "서버 데이터는 TanStack Query" |
| 서버를 바꾸는 요청(저장, 승인·발송, 이관, 조정) | TanStack Query (`useMutation`). 끝나면 관련 쿼리를 무효화해 다시 읽는다 | 3단계 지시. 무효화 방식은 `구현 선택` |
| 화면 안에서만 쓰는 값(열린 탭, 입력 중인 글, 열린 창) | 컴포넌트 상태 (`useState`) | 3단계 지시 "화면 내부 상태는 컴포넌트 상태" |
| 필터·정렬·쪽 | 주소의 쿼리 문자열. [목록으로]가 같은 목록으로 돌아오게 한다 | 정의서 v1 SCR-02 ③ "마지막 접수함 주소(필터·정렬·쪽)" |
| 상담원·부서·기준 시각 | 브라우저 저장소(localStorage)만. 다른 값은 브라우저 저장소에 두지 않는다 | 정의서 v1 0-4 "브라우저에 기억". 다른 값을 안 두는 것은 `제안 — 조장 확인` |

- 전역 상태 라이브러리(Redux 등)는 쓰지 않는다. 위 다섯 곳으로 충분하다 (`제안 — 조장 확인`).
- 서버 값을 `useState`에 복사해 두지 않는다. 고칠 수 있는 입력 칸의 처음 값으로만 복사한다 (`구현 선택`).
- 기본 설정(`src/queryClient.ts`): 4xx는 다시 시도하지 않고 5xx·연결 끊김만 한 번 더 시도한다. 쓰기 요청은 저절로 다시 시도하지 않는다. 창에 초점이 돌아올 때 다시 읽지 않는다 (`구현 선택`: 승인·발송이 두 번 나가지 않게, CLAUDE.md 규칙 3과 맞춤).
- 자동 갱신: 접수함·나의 업무 현황은 5분마다(`refetchInterval: 300_000`), 문의 상세는 처리 중일 때만 2초마다, 끝나면 멈춘다(근거: 정의서 v1 0-4, 기술 §8-2).
- 쿼리 키는 `[자원, 매개변수 객체]` 꼴로 쓰고, 상담원·부서·기준 시각이 결과를 바꾸면 키에 넣는다. 예 `["inbox", { dept, asOf, page, sort }]`, `["ticket", ticketId]` (`구현 선택`).

## 5. 공통 컴포넌트

`src/ui/`에 있다. 견본은 개발 서버의 `/ui` 주소에서 본다(개발 전용, 서비스 화면 아님).

| 컴포넌트 | 쓰는 곳 | 근거 |
|---|---|---|
| `Button` (기본·primary·ghost·danger, 작은 크기, busy) | 모든 버튼 | 3단계 지시 "버튼" |
| `Chip`, `StatusBadge`, `SlaBadge`, `AlertChip`, `PriorityBadge`, `formatRemaining` | 상태 6개, SLA 상태, 경고 4종, P1~P4, 남은 시간 "36.2h / −12.5h / 멈춤" | 3단계 지시 "상태 배지", 기술 §8-2, 정의서 v1 0-3 CP-1·CP-2, B-3 |
| `DataTable`, `nextSort` | 접수함, 업무 현황 목록, 참고 표 | 3단계 지시 "표". 로딩·빈 목록·흐린 이전 값은 정의서 v1 0-4 "읽기 실패" |
| `Modal` | 팝업 P1~P9 | 3단계 지시 "모달" |
| `PageHeader`, `Card`, `Tabs`, `Pager` | 화면 머리, 구역, 탭, 쪽 넘김 | 3단계 지시 "페이지 헤더". Card·Tabs·Pager는 목업에서 반복되어 `구현 선택` |
| `Banner`, `EmptyState`, `Field` | 안내 띠, 빈 상태, 입력 칸과 오류 글 | 정의서 v1 0-4 "읽기 실패 띠", §6 |

- 공통 컴포넌트는 API를 부르지 않고 주소를 모른다. 값과 콜백(`onClick`, `onChange`)만 받는다 (`구현 선택`).
- 기술 §8-2의 나머지 공통 부품("왜?" 팝오버 CP-3, 출처 링크 CP-4, 초안+대역 편집기 CP-5, 이관 사유 선택 CP-6)은 화면 지식이 필요해 4단계에서 해당 화면과 함께 `src/ui/`에 만든다 (`구현 선택`).
- 신뢰도 숫자는 어떤 컴포넌트에도 보이지 않는다(근거: 정의서 v1 0-3 CP-8, 화면 명세 Q4).

## 7. 오류 처리

| 상황 | 화면 반응 | 근거 |
|---|---|---|
| 서버 오류 전부 | `api.ts`의 `ApiError`(status, message, body)로 받는다. 화면은 `e instanceof ApiError ? e.message : 기본 문구`로 보인다 | 기존 코드 관례 |
| 400 입력 오류 | `fieldErrors(e)`로 칸별 문구를 꺼내 해당 `Field`의 `error`에 넣는다(칸 아래 빨간 글) | 화면 명세 각 SCR "입력 검증", 기존 api.ts |
| 404 없는 문의 | 접수함으로 돌아가 안내를 띄운다 | 명세서 FR-030 예외 1행, 기존 TicketDetailPage |
| 409 발송 막힘 | 발송 전 확인 창(SCR-03-P7)에 걸린 이유(body.issues)를 보인다 | 정의서 v1 0-4 "발송 관문", 기존 DraftCard |
| 읽기 실패(목록·상세) | 이전 값을 흐리게 유지하고(`DataTable stale`) "불러오지 못함. 새로고침" 띠(`Banner tone="neg"` + [새로고침]) | 정의서 v1 0-4 |
| 쓰기 실패 | 입력한 글을 지우지 않고 창·편집기 안에 오류 띠를 보인다 | `제안 — 조장 확인` |

- 브라우저 기본 `alert`·`confirm`·`prompt`는 쓰지 않는다. 확인은 `Modal`로 묻는다 (`구현 선택`).
- 고객에게 가는 글은 [승인·발송] → 발송 전 확인 창을 지난다. 화면에서 SENT를 직접 만들지 않는다(근거: CLAUDE.md 규칙 3, 정의서 v1 0-4 "발송 관문").

## 8. 접근성

- 색만으로 뜻을 나누지 않는다. 상태 배지·경고에는 늘 글자와 기호(✓ ! ⏸ →)를 함께 쓴다(근거: 정의서 v2 0-5).
- 버튼은 `<button type="button">`, 표의 누를 수 있는 줄은 Enter로도 열린다. 모달은 Esc로 닫히고 열릴 때 첫 칸에 초점이 간다 (`구현 선택`).
- 입력 칸은 `Field`로 감싸 이름표(label)와 오류 글이 칸에 이어지게 한다(aria-invalid, aria-describedby) (`구현 선택`).
- 아랍어 본문은 `dir="rtl"`로 보인다 (`구현 선택`, 목업 `--font-ar`).

## 9. 하지 않는 것

- 화면 명세에서 "만들지 않음"으로 정한 것(Q1 번역 토글, Q2 성과 차트, Q4 신뢰도 숫자 등)은 만들지 않는다(근거: 화면 명세 README Q1~Q11).
- 새 npm 패키지는 버전을 고정(`"5.62.0"`, ^ 없이)해 넣고, 넣은 이유를 PR에 적는다 (`구현 선택`: 기존 package.json이 모두 고정).
- API 키, `.env`는 커밋하지 않는다(근거: CLAUDE.md 규칙 8).
