# 슬라이스 5-1: 전화 상담(SCR-05)

4단계 다섯 번째 슬라이스(SCR-05~09)의 첫 화면. 브랜치 `feat/fe-phone`(`feat/fe-my-work`에서 갈라짐, 로컬 전용, push 안 함).

## 1. 명세

- [SCR-05 전화 상담](../screens/SCR-05-phone.md). 명세서 FR-050(AC-050-1~6), 기술 명세서 §12(통화 받아쓰기 1단계), D35·D36
- 원칙: [principles.md](../principles.md). 부품은 `src/ui/`, 값은 `src/styles/tokens.css`
- 목업 배치 기준: v1.42 `viewPhone`(위 통화 막대 → 왼쪽 대화 기록 / 오른쪽 판단·필수 정보 → 아래 통화 메모)

## 2. 구현 계획

| 무엇 | 어디 | 어떻게 |
|---|---|---|
| 화면 | `src/features/phone/PhonePage.tsx`, `phone.css`, 주소 `/phone` | 왼쪽 메뉴 "전화 상담" |
| 위 막대: 녹음 올리기 | 같은 파일 | 녹음 파일·고객 ID·고객 언어·제품 코드·접수 시각 + [받아쓰기]. 오른쪽에 파일 길이 m:ss, 고객사·나라·등급(`GET /ref/customers`) |
| 왼쪽: 받아쓴 대화 | `Transcript` | 발화마다 상담원/고객, 시작 시각, 고칠 수 있는 글. 빈 시간은 그 뒤 첫 발화 앞에 빨간 줄 "받아쓰지 못한 구간 m:ss–m:ss (이유)" |
| 오른쪽: 판단·필수 정보 | `Provided` | 긴급도만. 메모 Provided 값마다 ✓(몇 번째 발화) / "받아쓴 글에서 찾지 못함", "필수 정보 a/b" |
| 아래: 통화 메모 초안 | 같은 파일 | 영어 메모(고칠 수 있음), 가린 곳 n, "[접수] 전에는 아무것도 저장되지 않습니다", [메모 다시 만들기]·[접수] |
| 접수 | `POST /tickets` | 채널 PHONE, 본문 = 확인한 메모, 접수 시각을 비우면 통화 시작(지금 − 녹음 길이, C-181) |
| 접수 시뮬레이터 | `IntakePage.tsx` | 슬라이스 3에서 잠시 두었던 통화 녹음 칸(`CallPanel`)을 지우고 이 화면으로 옮김 |
| 시험 통화 | `e2e/calls/make_calls.py` | 운영진 데이터에 녹음이 없어 대본을 기계 음성(espeak-ng)으로 읽혀 만든다. 또렷한 통화와 가운데 20초 잡음 통화. 파일은 커밋하지 않음(`e2e/calls/out/`) |
| 시험 | `e2e/scr-05.spec.ts` | 실제 받아쓰기·메모 초안(Gemini). 목은 AC-4·AC-6만 |

"필수 정보 a/b"의 b는 메모에 든 항목 수다(구현 선택). 받아쓰기 응답에는 유형별 필수 항목 전체 목록이 없고, 유형은 접수 뒤에 정해진다.

## 4. 수용 기준 확인

2026-10-29, 실제 API 위에서 SCR-05 시험 6개 통과.

| AC | 결과 | 비고 |
|---|---|---|
| SCR-05-AC-1 | 통과(실제 받아쓰기) | 2분 37초 통화, 발화 26개, 상담원·고객 번갈아, 빈 구간 없음 |
| SCR-05-AC-2 | 통과(실제 받아쓰기) | 빈 구간 줄이 발화 사이에 시각과 함께. 잡음이 덮은 줄(오류 코드 E17 문답)이 받아쓴 글에 없음 |
| SCR-05-AC-3 | 통과(실제 받아쓰기) | 제조번호 ✓, 값과 메모 Provided 값이 같음 |
| SCR-05-AC-4 | 통과(목) | 실제 응답의 제조번호 값만 받아쓴 글에 없는 값으로 바꿈 → "받아쓴 글에서 찾지 못함", 필수 정보 n−1/n |
| SCR-05-AC-5 | 통과(실제 접수) | 받아쓰기 뒤에도 티켓 없음 → [접수] → 채널 PHONE, 본문 = 고친 메모, [티켓 상세 보기] |
| SCR-05-AC-6 | 통과(목 + 실제 접수) | 502 "받아쓰기 실패" + [다시 받아쓰기], 메모 칸에 직접 써서 접수 |

### 확인하며 알게 된 것

- 시험 통화는 2분 37초다. 명세의 "약 3분"보다 조금 짧다. 대본을 늘리면 맞출 수 있다.
- 제조번호는 받아쓴 글에 하이픈 없이 "LVB202400117"로 적혔다. 대조는 같은 글자라 ✓이고, AC-3 시험은 하이픈·공백을 빼고 비교한다.
- 잡음 통화에서 빈 구간은 잡혔지만, 받아쓰기가 준 시각이 실제 잡음 자리(1:08–1:28)보다 약 40초 늦게(1:48–2:09) 나왔다. 그 뒤 발화 시각도 함께 밀려 끝이 녹음 길이를 넘는다. 화면은 받은 시각을 그대로 보인다. 받아쓰기 시각의 정확도는 백엔드 L9 쪽 확인 거리다.
- AC-4는 실제 모델로 만들 수 없었다. 고객이 철자를 풀어 말한 글로 메모를 다시 만들어도, 모델이 받아쓴 글 그대로 옮겨 적어 대조가 통과했다. 그래서 "모델이 잘못 쓴 상태"를 목으로 만들었다.
- 목업을 따른 곳(구현 선택): 카드 배치, "시스템이 판단한 것"·"필수 정보" 오른쪽 열, 아래 통화 메모와 오른쪽 아래 버튼.
- 명세를 따른 곳(목업과 다름): 통화 중 시계·보류·음소거·연결 버튼 대신 녹음 올리기, 한국어 번역 줄 없음, 판단 칸은 긴급도만, "다음에 물어볼 것"·대기 중인 전화·상담원 현황 탭 없음.
