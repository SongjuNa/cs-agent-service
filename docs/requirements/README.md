# requirements — 요구사항

## 목적
프로젝트의 **기능 요구사항(FR)**, **비기능 요구사항(NFR)** 및 검증 가능한 인수 기준을 관리합니다.

## 관리 대상
- `functional-requirements.md` — 기능/비기능 요구사항을 통합하거나, 규모에 따라 분리할 수 있는 기본 문서(내용 확정 후 추가)

## 작성 규칙
- 요구사항별로 안정적인 ID(예: `FR-001`, `NFR-001`)를 부여합니다.
- 기능명, 설명, 우선순위(MVP/확장/제외), 입력/출력, 예외, 인수 기준을 **필요한 수준만** 기록합니다.
- 동일 기능의 현재 명세를 한 곳에만 유지하고, 과거 버전은 Git 이력에서 조회합니다.
- AI 구현 작업은 요구사항 ID를 [OpenSpec 변경 명세](../../openspec/README.md)에 연결해 추적합니다.
- API 형식은 실제 OpenAPI 계약과 충돌하지 않도록 점검합니다.

## 변경 절차
변경 사유 확인 → 요구사항 본문 및 영향 범위 수정 → 팀 리뷰/PR → 관련 구현 명세·테스트 확인. 요구사항 변경을 AI 코딩 도구가 임의 확정하지 않도록 합니다.
