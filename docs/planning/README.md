# planning — 프로젝트 기획

## 목적
프로젝트가 **왜 필요한지, 무엇을 언제까지 누구와 만들지**에 대한 확정된 기준을 관리합니다.

## 관리 대상
- `project-plan.md` — 프로젝트 기획서의 Markdown **단일 편집 원본** (현재 v1.3)
- `exports/project-plan.html` — 웹 열람 및 제출용 최신 HTML (업로드 예정)
- `exports/project-plan.pdf` — 인쇄 및 제출용 최신 PDF (업로드 예정)
- 필요 시 배경 분석 근거 및 확정 범위에 대한 참조 링크

## 포함할 내용
추진 배경, 문제 정의, 목표·성공 지표, 사용자, MVP·확장·제외 범위, 주요 구성 개요, 일정/WBS 요약, 담당 역할, 위험 및 대응. 기능별 상세 구현 명세는 중복 작성하지 않습니다.

## 편집 원본과 제출용 산출물의 구분

| 경로 | 역할 | 직접 내용 수정 여부 |
| --- | --- | --- |
| `project-plan.md` | 유일한 편집 원본 | 검토·합의 후 수정 |
| `exports/project-plan.html` | 브라우저 열람/제출용 최신 결과물 | 금지. 원본 또는 변환 소스를 수정 후 다시 내보냄 |
| `exports/project-plan.pdf` | 인쇄/제출용 최신 결과물 | 금지. 원본 또는 변환 소스를 수정 후 다시 내보냄 |

- 파일명에 `v1.0`, `v1.1` 등을 붙이지 않습니다. **버전은 문서 내부 표기와 Git 커밋 이력으로 관리**합니다.
- Markdown을 수정한 경우 HTML/PDF도 같은 문서 버전으로 다시 생성·검수합니다. 업데이트하지 못한 이전 산출물을 최신 버전으로 표시하지 않습니다.
- HTML/PDF의 레이아웃은 전용 CSS나 템플릿을 사용해 생성할 수 있으며 Markdown과 바이트 단위로 같을 필요는 없습니다. 그러나 내용이 원본과 모순되지 않아야 합니다.
- 기존에 작성한 v1.1 HTML/PDF를 등록할 때에는 파일 **내용을 임의 변경하지 않고 이름과 저장 위치만 통일**합니다.
- 문서 내용, 표, 링크, 그림, 제목, 메타데이터를 승인 없이 보정하지 않습니다. 원본에 있는 잘못된 링크나 누락된 이미지는 별도로 보고하고 합의 후 정정합니다.

## Git 및 버전 관리

1. v1.0, v1.1 등 수정 사항은 같은 `project-plan.md`에 순서대로 커밋합니다. 이전 버전은 Git History에서 조회합니다.
2. 리뷰는 작업 브랜치/Pull Request에서 진행하며 `main` 병합은 팀 승인 뒤 수행합니다.
3. 가급적 Markdown과 이에 대응하는 최신 HTML/PDF를 **같은 PR**에서 검토합니다.
4. 공식 제출 시점의 HTML/PDF는 `project-plan-v1.1.html`, `project-plan-v1.1.pdf`처럼 명시적으로 버전을 표시하여 **GitHub Release 첨부 파일**로 보존할 수 있습니다. Git 태그는 저장소의 커밋을 가리키므로 개별 파일 버전과 구별합니다.
5. 버전별 복제 폴더(`v1.0/`, `v1.1/`)는 만들지 않고, `exports/`에는 최신 제출용 산출물만 둡니다.
6. Zip 배포 패키지나 포함된 외부 서체 등은 별도 배포가 필요한지와 라이선스를 확인한 뒤 보관합니다. 기본 `exports/`에는 HTML/PDF만 둡니다.
7. 내용 업데이트 후 브라우저 표시, PDF 페이지/한글/다이어그램, 링크 및 문서 버전 일치 여부를 검증합니다.
8. 기획 범위를 수정할 때에는 [requirements](../requirements/README.md)와 [OpenSpec](../../openspec/README.md)에 미치는 영향을 확인합니다.

## HTML/PDF 내보내기 및 검증

- 현재 첨부된 HTML은 **단일 파일 HTML**이므로 별도의 폰트 파일이나 ZIP 내부 자산을 추가로 복제하지 않습니다.
- HTML과 PDF는 원본 Markdown을 기초로 작성한 제출용 결과물로 취급하며, 새 버전 내보내기 시 파일명이 아닌 **문서 내부 버전**을 먼저 확인합니다.
- 파일 업로드 후 동일 파일 여부는 크기 및 SHA-256 등 체크섬으로 확인하는 것을 권장합니다.
- `exports/`의 임시 `.gitkeep`은 실제 HTML 또는 PDF 등록 시 삭제해도 됩니다.

> 이 README의 저장·관리 정책은 실제 HTML/PDF 파일 등록 여부를 보증하지 않습니다. 파일은 GitHub에 업로드된 뒤에만 등록 완료로 표시할 수 있습니다.
