# Spec Delta: compound-inquiry

## Purpose

본문의 서로 다른 요청을 하위 문의로 나눠 각각 처리하고, 준비된 하위 문의부터 상태 목록이 붙은 답변 메일을 만든다(명세서 v1.5 FR-006, FR-022, D15·D16).

## ADDED Requirements

### Requirement: 복합 문의 분리 (FR-006)
분류 결과에 서로 다른 유형의 요청이 둘 이상이면 요청마다 하위 문의(순번 1..n, 본문 순서)를 만들고 복합 문의 표시(multi_yn)를 켜야 하며, 하위 문의마다 자기 유형·근거 문장·긴급도로 추출·규칙·근거·초안을 따로 계산해야 한다(MUST)(근거: FR-006 처리 1~5, 기술 명세서 §2-1). 한 하위 문의의 처리가 실패해도 나머지는 계속해야 한다(MUST)(근거: FR-006 예외 3행).

#### Scenario: AC-006-1 펌웨어 + 매뉴얼
- **GIVEN** CSV1-000008(펌웨어 업데이트와 매뉴얼 요청)
- **WHEN** 분류한다
- **THEN** category_code에 FW_UPDATE와 MANUAL이 ';'로 들어 있고 multi_yn이 켜지며 하위 문의 처리 2개가 만들어진다

#### Scenario: AC-006-2 단일 견적 문의
- **GIVEN** CSV1-000004(견적 문의)
- **WHEN** 분류한다
- **THEN** category_code = "QUOTE", multi_yn은 꺼져 있고 처리는 1개다

#### Scenario: AC-006-3 하위 문의별 규칙
- **GIVEN** 복합 문의 티켓
- **WHEN** 실행 로그를 본다
- **THEN** 하위 문의별 run이 각자의 유형으로 우선순위·부서·SLA 목표를 계산했다

#### Scenario: AC-036-4 실행 나누기
- **GIVEN** CSV1-000008(복합)
- **WHEN** 실행 로그를 본다
- **THEN** 문의 1·2의 run이 따로 있고 답변 구성 단계(T5)는 티켓 run(순번 없음)에 있다

### Requirement: 복합 문의 답변 구성 (FR-022)
복합 문의에서 답변 초안이 생긴 하위 문의마다 다른 하위 문의를 기다리지 않고 인사말·단락·문의 상태 목록·맺음말로 된 메일 초안(FINAL_REPLY DRAFT, 그 하위 문의 순번)을 만들어야 한다(MUST)(근거: FR-022 처리 1·3·4·6). 상태 목록은 하위 문의마다 한 줄이고 예상 완료 시각이나 SLA 목표 시간을 넣지 않아야 하며, 초안이 없거나 실패한 하위 문의는 "담당자 확인 중"으로 적어야 한다(MUST)(근거: FR-022 처리 3·7, 부록 A-2). 메일마다 자체 대조를 해야 하고, 발송하면 그 메일이 답한 하위 문의만 RESOLVED가 되어야 한다(MUST)(근거: FR-022 처리 5·6).

#### Scenario: AC-022-1 먼저 준비된 하위 문의의 메일
- **GIVEN** CSV1-000008에서 FW_UPDATE 하위 문의의 초안이 준비됨
- **WHEN** 답변을 구성한다
- **THEN** 펌웨어 단락(RN 인용)과 "2. …" 상태 줄이 있는 메일 초안이 생긴다

#### Scenario: AC-022-2 그 하위 문의만 해결
- **GIVEN** 위 메일을 발송
- **WHEN** 상태를 본다
- **THEN** FW_UPDATE 하위 문의만 RESOLVED이고 MANUAL 하위 문의는 그대로다

#### Scenario: AC-022-3 근거 없는 하위 문의
- **GIVEN** 한 하위 문의의 근거 후보가 비어 있는 복합 문의
- **WHEN** 다른 하위 문의의 메일을 만든다
- **THEN** 상태 목록에 그 문의가 "담당자 확인 중" 줄로 있고 그 문의에 "근거 없음"이 표시된다

#### Scenario: AC-022-4 기한 없는 상태 목록
- **GIVEN** 문의 상태 목록
- **WHEN** 본문을 검사한다
- **THEN** SLA 목표 시간이나 완료 예정 시각이 없다

#### Scenario: 인사말 실패
- **GIVEN** L5 호출이 두 번 실패
- **WHEN** 메일을 만든다
- **THEN** 고정 인사말·맺음말(F-2)로 메일이 만들어진다
