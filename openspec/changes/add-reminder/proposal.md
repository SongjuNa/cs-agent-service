# Proposal: 회신 요청 리마인드 (add-reminder)

## Why

정보 요청을 보낸 뒤 고객 회신이 126시간 동안 없으면, 시스템이 고정 문안으로 회신 요청 리마인드를 바로 자동 발송해야 한다(근거: 명세서 v1.5 FR-023 기능 설명, D29). 고객에게 가는 글 중 상담원 승인 없이 나가는 유일한 예외다(근거: FR-023 수행 주체, D32). 주기 점검의 2단계 자리가 비어 있다(근거: 기술 명세서 v1.4 §6-4 주기 점검 2, 이 변경 전 `app/scheduler.py` 머리 주석 "14번 변경에서 붙인다").

## What Changes

- **리마인드 (`app/status/reminder.py`)**: WAITING_CUSTOMER이고 마지막 INFO_REQUEST SENT + 126시간 ≤ 기준 시각이며 그 뒤 CUSTOMER_REPLY가 없고 REMINDER 행이 아직 없는 하위 문의에, 고정 문안 + 막는 항목 라벨로 PROGRESS_NOTICE(notice_transition REMINDER) SENT(sender SYSTEM) 한 행을 쓴다(근거: FR-023 처리 1~4, 기술 명세서 §6-4 주기 점검 2). 문안의 항목은 FR-023 입력 "정보 요청에 쓴 빠진 항목"을 따른다. 에이전트 설계서 부록 A-1은 "막는 항목"이라 다르다(C-77).
  - 상태와 1차 응답 시각은 바꾸지 않는다. 문의당 한 번(근거: FR-023 처리 4, schema.sql ticket_message_one_reminder).
  - 문안에 SLA 목표 시간, 예상 완료 시각을 넣지 않는다(근거: FR-023 처리 2, AC-023-8, 에이전트 설계서 부록 A).
  - 고객 언어 템플릿이 없으면 영어 템플릿으로 보내고 "영어로 발송"을 돌려준다. 이 표시를 담을 열이 없어 저장하지 않는다(C-78)(근거: FR-023 예외 1행, CLAUDE.md 규칙 4).
  - 언어 모델을 부르지 않는다(근거: FR-023 수행 주체, 기술 명세서 §3-1 "회신 리마인드(FR-023)는 LLM을 쓰지 않는다").
- **템플릿 (`app/templates/reminder/en.txt`)**: 에이전트 설계서 부록 A-1의 영어 원문. 부록 A는 "제안"이고 T40은 영어 원문을 팀이 확정하라고 하므로, 팀 확정 전 임시 문안이다(C-74)(근거: 에이전트 설계서 부록 A-1, T40).
- **주기 점검 (`app/scheduler.py`)**: 경고 → 해제 → 리마인드 → 종료 순서. 리마인드 뒤 한국어 대역(L7)을 언어 모델 호출 계층으로 붙인다. 대역이 실패해도 리마인드는 남는다(근거: §6-4 주기 점검 순서와 2 "대역(L7)은 만든다", FR-039).

## Capabilities

### New Capabilities
- `reminder`: 126시간 회신 요청 리마인드 자동 발송과 대역.

## 범위 밖

- **14개 언어 템플릿**: T40 절차(영어 원문 팀 확정 → 언어 모델로 한 번 번역 → 사람 검수 → 파일 고정)가 필요하다. 이 변경은 영어 원문만 두고 나머지 언어는 예외 1행대로 영어로 보낸다(C-74)(근거: 에이전트 설계서 부록 A T40, FR-023 예외 1행).
- **화면 표시("리마인드 자동 발송 {시각}", "리마인드 발송됨")**: 접수함 18번, 티켓 상세 19번, 나의 업무 현황 20번(근거: FR-023 출력, `bootcamp/openspec/2순위_시작_전후비교.md` 결정 2의 변경 순서 18~20번).
- **리마인드 초안 행(APPROVED)**: FR-023 처리 3·AC-035-6은 APPROVED + SENT 두 행이지만 기술 명세서 §6-4는 "바로 SENT"이고 schema.sql의 부분 유일 색인이 REMINDER 행을 문의당 하나만 허용한다. SENT 한 행만 쓴다(C-75). 승인 주체 표기는 에이전트 설계서 §12-3에서도 미정이다(근거: 기술 명세서 §6-4 주기 점검 2, schema.sql ticket_message_one_reminder, 에이전트 설계서 §12-3, CLAUDE.md 규칙 4).
- **복합 문의에서 회신 행이 NULL일 때의 조건**: 16번(근거: 개발_결정_기록 변경 13 범위 밖).
- **주기 점검의 실행 로그**: 리마인드 발송을 실행 로그(agent_run)에 남기는 일은 15번(근거: 기술 명세서 §6-5, FR-036, 개발_결정_기록 C-61).
- **검증(L8)**: 리마인드는 검증을 거치지 않는다(근거: FR-049 처리 8, 기술 명세서 §3-1).
- **CLAUDE.md 규칙 3 문구**: 규칙 3은 "SENT로 바꾸는 것은 상담원 승인 API뿐"이라 리마인드 예외(D29, 기술 명세서 §1-3 원칙 7)가 적혀 있지 않다. 고치지 않고 묻는다(C-79)(근거: CLAUDE.md 규칙 3, 명세서 FR-023 머리말).

## Impact

- 새 파일: `backend/app/status/reminder.py`, `backend/app/templates/reminder/en.txt`, 시험 파일(근거: design 결정 1·2).
- 고치는 파일: `backend/app/scheduler.py`(2단계), `backend/app/db/store.py`(대역 함수), `backend/app/main.py`(대역 함수 넘기기)(근거: design 결정 3).
- DB 구조는 고치지 않는다(근거: CLAUDE.md 규칙 4).
