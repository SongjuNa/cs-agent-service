# Proposal: 자동 발송 — 검증 AI가 확인해 사람 승인 없이 보내기 (add-auto-send)

## Why
최신 목업에는 간단한 문의를 검증 AI가 확인해 사람 승인 없이 보내고, 상담원이 접수함의 "자동 처리" 탭에서 **사후 검수**하는 흐름이 있다(자동 처리 규칙 화면, 접수함 자동 처리 탭, 나의 업무 현황 "AI 자동 처리" 카드, 운영 대시보드의 AI 처리 비중). 저장소는 **CLAUDE.md 규칙 3("고객에게 가는 글은 DRAFT만, 자동 발송 없음")과 D32**, DB 제약(`ticket_message_kind_combo`: SENT는 AGENT만, 리마인드만 SYSTEM 예외)이 이를 막고 있다. 팀 합의(2026-10-31)로 목업이 최신 기준이고, **규칙 3을 바꿔 구현해도 된다는 사용자 허락을 받았다**(나중에 정리 보고).

## What Changes
1. **자동 판정 엔진** `app/rules/autosend.py`(순수 함수). 목업 `lib/auto.ts`의 조건을 서버로 옮긴다. 모두 만족해야 자동 발송, 하나라도 걸리면 상담원이 확인한다.
   - 자동 처리 켜짐, 채널 켜짐, 유형이 **자동 대상**(MANUAL·TECH_SPEC·FW_UPDATE 기본 켜짐, COMPLIANCE 기본 꺼짐), **항상 사람 확인 유형**(DEFECT·INSTALL·RETURN·WARRANTY·QUOTE·ORDER_LEAD)이 아님
   - 우선순위 P3·P4, 긴급도가 안전·설비 정지가 아님, 단일 문의(복합 제외), 막는 정보 누락 없음, 근거 문서 있음
   - 답변 초안이 있고 **검토 표시 5개가 모두 통과**(인용·숫자, 막는 항목, 확인 표시, 안전 문의 아님, ⑤ 검증 통과). 상담원 발송 API가 막는 "확인이 필요한 것"(issues)이 하나라도 있으면 자동 발송하지 않는다.
2. **자동 발송 실행**: 접수 처리가 끝난 뒤(초안·검증 완료) 판정이 통과하면 **상담원 발송과 같은 길**로 보낸다. 보내는 쪽은 `SYSTEM`, 이름은 `AI_AUTO`. 상태 전이는 같은 `FINAL_REPLY_SENT`(→ RESOLVED), 행위자만 `AI_AUTO`.
   - 실제 메일 전송은 이 시스템에 연동되어 있지 않다. "보냄"은 기존 상담원 발송과 같이 **발송 기록을 남기는 것**이다.
3. **사후 검수**: 자동 발송된 문의는 상담원이 나중에 확인한다. 검수 완료를 기록하는 API.
4. **자동 처리 규칙 설정**: 켜기/끄기, 유형별·채널별 대상 여부. 저장하고 읽는 API.
5. **화면**: 자동 처리 규칙 화면(`/admin/auto`), 접수함 "자동 처리" 탭과 줄 표시, 문의 상세의 자동 발송·사후 검수 표시, 나의 업무 현황 "AI 자동 처리" 카드, 운영 대시보드 "AI 자동 처리율"·"AI와 사람이 나눠 처리한 비중".

## ⚠️ 규칙 변경 (팀 보고용)
- **규칙 3**: 고객에게 가는 글을 **상담원 승인 없이** 보내는 경로를 만든다. 아래 안전장치로 범위를 좁힌다.
- **규칙 4**: 새 표 2개(`svc.auto_setting`, `svc.auto_review`), `ticket_message` CHECK 제약 변경.
- **D32**("자동 발송 없음") 와 `status_transition` 표 설명 문구 갱신.

## 안전장치 (설계의 핵심)
- **고위험은 코드로 막는다.** 항상 사람 확인 유형, 우선순위 P1·P2, 안전·설비 정지, 복합 문의, 막는 정보 누락, 근거 없음은 설정으로 풀 수 없다(목업의 "고정 기준 · 설정으로 바꿀 수 없음").
- **한 번에 끌 수 있다**: 자동 처리 전체 스위치. 꺼지면 어떤 문의도 자동 발송하지 않는다.
- **발송 방식은 상담원 발송과 같은 검사를 통과해야 한다.** 새 우회로를 만들지 않고 같은 함수를 `auto=True`로 부른다.
- **되돌릴 수 있게 기록한다**: 자동 발송은 이력에 "AI 자동 발송"으로 남고, 검수 대기/완료가 보인다.
- **기본값**: 목업과 같이 켜짐. 실제 메일을 연동할 때는 먼저 꺼야 한다(PR에 적음).

## 범위 밖
- 목업의 "챗봇 해결" 구분(챗봇이 대화에서 바로 해결): 챗봇 채널 연동이 없다.
- 자동 발송 후 고객 회신 처리, 정보 요청(INFO_REQUEST) 자동 발송(최종 답변만 자동 대상).

## Impact
새 표 2개와 CHECK 변경(`schema.sql`·`table-specification.md`), `rules/autosend.py`, `status/autosend.py`(실행·검수), 처리 끝 연결(`api/tickets.py` process), `api/autosend.py`(설정·검수), 접수함 `auto` 필터·`counts.auto`·`auto_state`, 화면 5곳, 시험.
