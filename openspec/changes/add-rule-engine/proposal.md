# Proposal: 규칙 엔진 (add-rule-engine)

## Why

문의 하나가 들어오면 우선순위, 담당 부서, 빠진 필수정보, SLA 목표 시간을 정해야 한다. 이 네 가지는 언어 모델이 아니라 규칙표(ref 스키마)가 정한다(근거: config.yaml 설계 원칙 2(우선순위·부서·SLA 목표), 기술 명세서 v1.4 §5-4(필수정보), CLAUDE.md 규칙 1). 2번 변경에서 규칙표를 채웠으므로 이제 표를 읽어 값을 정하는 코드를 만든다(근거: 프로젝트 구조 1순위 판 6장 3번 `add-rule-engine` = FR-010~014).

## What Changes

- **고객·제품 조회 (FR-010)**: customer_id로 고객 등급·세그먼트·국가와 대표 연락처를, product_code로 제품 값 묶음을 읽는다(근거: 명세서 FR-010 처리 1·2).
- **우선순위 계산 (FR-011)**: 우선순위 규칙을 rule_order 순으로 보고 처음 맞는 규칙의 P1~P4와 rule_id, 판정 과정(규칙마다 맞음/안 맞음)을 돌려준다. 조건은 코드에 적지 않고 두 조건 표(priority_rule_urgency, priority_rule_category)에서 읽는다(근거: 명세서 FR-011 처리 1~4, 기술 명세서 §5-2).
- **부서 배정 (FR-012)**: `RT-{family}-{category}` 행에서 부서와 이관 조건을 읽는다. 반품은 반품 사유 단어 목록으로 불량/비불량/미확인을 정하고, 비불량이면 RT-ALL-RETURN-NON_DEFECT(SCM)를 쓴다(근거: 명세서 FR-012 처리 1~6, 기술 명세서 §5-3).
- **반품 사유 단어 목록 설정 파일 (W10의 일부)**: `config/return_reason_words.yaml`을 만든다. 내용은 반품 사유 단어 목록 v1(비불량 25개, 불량 12개)이다(근거: 기술 명세서 §5-3 4번, §9 W10, 반품_사유_단어목록_v1_20261022.md 4장).
- **필수정보 확인 (FR-013)**: (family, category)의 필수 항목에서 제공 항목을 빼 missing_info와 missing_blocking_info를 field_order 순으로 정한다(근거: 명세서 FR-013 처리 1~3, 기술 명세서 §5-4).
- **SLA 목표 설정 (FR-014)**: (category, customer_tier, priority) 행에서 sla_id와 1차 응답·해결 목표 시간을 읽는다(근거: 명세서 FR-014 처리 1~3, 기술 명세서 §5-4).
- **4,000건 재현 시험 (W1 완료 기준)**: tickets.csv 4,000건에서 우선순위 규칙·SLA 목표·필수정보가 100% 같은지 시험한다(근거: 기술 명세서 §9 W1 완료 기준, 2번 변경 proposal "범위 밖"에서 이번 변경으로 넘김).

## Capabilities

### New Capabilities
- `rule-engine`: 규칙표(ref)를 읽어 고객·제품 값, 우선순위, 부서, 빠진 필수정보, SLA 목표를 정하는 동작.

### Modified Capabilities
- 없음.

## 범위 밖

- **결과를 svc.sub_ticket에 저장하기 (구현 선택)**: 이번 변경은 값을 계산해 돌려주기만 한다. 저장(기술 명세서 §5-4 "목표 시간은 sub_ticket에 복사해 저장")은 접수와 처리 흐름(pipeline)을 만드는 변경에서 한다. 기준 문서가 정한 나눔이 아니라 변경을 작게 나누려는 선택이다.
- **화면 부분 (AC-010-2의 제품 드롭다운, AC-010-3, AC-012-3의 사유 고르기 화면)**: 1순위 화면은 티켓 상세 최소판(SCR-03M) 하나뿐이고(근거: config.yaml), SCR-03M에는 제품 드롭다운과 반품 사유 선택이 없다(근거: 화면 정의서 v2 SCR-03M). 그래서 1순위에서는 만들지 않는다. 이번에는 함수가 고른 값(제품, 반품 구분)을 받아 다시 계산하는 데까지만 만든다.
- **상담원이 바꾼 내용의 변경 기록 (FR-013 예외 "변경 기록을 남기고")과 실행 로그 기록 (FR-010·014 예외)**: 저장이 필요하고 실행 기록 FR-036은 2순위다(근거: 프로젝트 구조 1순위 판 4장 "1순위에서는 서버 로그로 충분"). 이번에는 서버 로그(경고)만 남긴다.
- **"배정 규칙 없음"일 때 접수함에 GCS_L1로 보이기 (FR-012 예외)**: 접수함 FR-029는 2순위다(근거: 프로젝트 구조 1순위 판 4장).
- **우선순위 조정 (AC-014-2의 P3 조정과 변경 이력)**: FR-028은 2순위다(근거: config.yaml 설계 원칙 6). 이번에는 규칙값 P4로 72시간/168시간만 확인한다.
- **팀 정답지 채점 (AC-011-4, AC-012-5, AC-013-4, AC-014-3)**: 팀 정답지 적재(W9)와 채점 배치(W4)를 1순위 구조에서 뺐다(근거: 프로젝트 구조 1순위 판 4장). 단, 기술 명세서 §9 W9에는 팀 정답지 v1(gold_set_v1.csv 80행)이 정의되어 있어 두 문서가 다르다(조장 확인 필요). 이번에는 위 4,000건 재현 시험을 한다.
- **팀 보충 이관 규칙 `config/escalation_rules_team.yaml`(W10의 나머지)**: 이관 후보 FR-020은 3순위다(근거: 프로젝트 구조 1순위 판 4장).
- **영어가 아닌 반품 문의의 단어 판정**: L2(5번 변경)가 영어로 바꾼 사유가 있어야 시험할 수 있다(근거: 반품_사유_단어목록_v1_20261022.md 3장).

## Impact

- 새 파일: `backend/app/rules/` 아래 모듈, `config/return_reason_words.yaml`, `backend/tests/rules/`(4,000건 재현), `backend/tests/acceptance/`(AC 시험)(근거: 프로젝트 구조 1순위 판 2장 tests/rules/, tests/acceptance/).
- 고치는 파일: `backend/pyproject.toml`(YAML 읽기 라이브러리 `pyyaml` 추가. 근거: 설정 파일이 YAML이라서, 기술 명세서 §5-3 4번).
- DB 구조(`docs/database/schema.sql`)는 고치지 않는다.
