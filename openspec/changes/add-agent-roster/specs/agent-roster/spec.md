# Spec Delta: agent-roster

## Purpose

하위 문의마다 담당 상담원(지어낸 이름)을 두어 나의 업무 현황의 "내 담당"이 동작하게 한다(기술 명세서 v1.4 §8-3, 조장 결정 2026-10-23).

## ADDED Requirements

### Requirement: 가상 상담원 명단
시스템은 운영진 데이터에 상담원이 있는 11개 부서마다 12명, QA_CLAIM·RND_FW에는 시연용 1명씩의 지어낸 이름을 명단으로 가져야 하고, 이름은 모두 달라야 하며, 운영진 데이터의 상담원 ID마다 명단의 한 사람이 짝지어져야 한다(MUST)(근거: tickets.csv assignee_masked, 명세서 v1.5 FR-033 처리 10, 조장 결정 2026-10-23).

#### Scenario: 명단 읽기
- **GIVEN** 명단 파일
- **WHEN** `GET /ref/agents?dept=TS_LV`를 부른다
- **THEN** TS_LV 상담원 12명의 이름이 명단 순서로 온다(QA_CLAIM·RND_FW는 시연용 1명)

### Requirement: 새 문의 담당 배정
처리 흐름이 담당 부서를 정해 저장할 때 담당 상담원이 비었거나 다른 부서 명단 사람이면, 그 부서에서 미해결 문의를 가장 적게 맡은 사람(같으면 명단 순서)을 넣어야 하고, 명단 밖 값은 그대로 두어야 한다(MUST)(근거: 조장 결정 2026-10-23, C-127, C-128).

#### Scenario: 차례로 배정
- **GIVEN** TS_LV 명단 사람들이 맡은 미해결 문의 수
- **WHEN** TS_LV 문의 두 건을 접수한다
- **THEN** 두 건은 그때 가장 적게 맡은 TS_LV 사람에게 차례로 가고 서로 다른 사람이 맡는다

#### Scenario: 부서가 바뀌면 다시 배정
- **GIVEN** TS_LV 사람이 맡은 문의
- **WHEN** 상담원 수정으로 담당 부서가 바뀐다
- **THEN** 새 부서 명단의 사람이 맡는다

### Requirement: 재생 담당 값
재생 채점은 scoring에 넣을 때 정답지 상담원 ID를 명단 이름으로 바꿔 넣어야 하고, scoring을 나의 업무 현황 집계로 거를 때 그 이름의 [내 담당]이 그 사람 문의만 세야 한다(MUST)(근거: 조장 결정 2026-10-23, C-118, FR-047).

#### Scenario: 재생 뒤 내 담당
- **GIVEN** 운영진 4,000건을 재생한 scoring
- **WHEN** CSV1-000017 담당(TS_LV_AGENT_09)의 짝 이름으로 scoring의 [내 담당]을 센다
- **THEN** 그 사람이 맡은 미해결 문의만 센다
