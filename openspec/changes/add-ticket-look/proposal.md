# Proposal: 문의 상세 모양을 최신 목업에 맞춤 (add-ticket-look)

## Why
2026-11-01 목업과 나란히 비교한 결과 문의 상세 머리·띠 모양이 달랐다. 화면만 바꾼다(서버·API·DB 변경 없음).

## What Changes
- 머리: 둥근 뒤로 단추([접수함으로] 이름 유지), 티켓 번호 옆 상태 칩, 큰 AI 요약(제목 크기).
- "지금 할 일": 파란 왼쪽 띠, "내 차례" 강조, "AI 처리 범위: 접수·분석·초안(자동 발송 건은 +발송)" 줄.
- 숫자 6칸은 얇은 줄로 줄였다.

## 추가한 것 (2차)
- 열어 둔 문의 탭 막대(접수함 탭 + 연 문의마다 한 탭, 닫기). 서버와 무관한 화면 상태라 브라우저 탭(sessionStorage)에만 둔다. 문의 상세와 접수함 위에 보인다.
- "AI 판단" 칩 줄: 우선순위·유형·긴급도·필수 정보 n/m, [더보기]에 담당·기한. 서버 값을 그대로 보이고, 칩을 누르면 아래 "시스템이 판단한 것"의 그 줄로 이동한다.
- 머리의 [근거 전체](= "시스템이 판단한 것" 구역으로 이동)와 [이관](= "답변 초안" 칸 위에 있던 버튼을 머리로 옮김. 기존 이관 창을 그대로 씀).
- 카드 제목: "고객이 보낸 것" → "고객 문의 원문", "보낼 것" → "답변 초안"(화면 제목과 접근성 이름 함께).

## 하지 않은 것
- 목업의 ⋯ 메뉴("초안 다시 만들기"): 저장소는 같은 일을 하는 [다시 처리] 버튼이 이미 보여서 메뉴로 숨기지 않았다.
- 고객 원문 옆 한국어 번역: 서버에서 원문을 번역해 저장해야 해서 별도 변경으로 나눈다(언어 모델 호출 추가).
- 숫자 6칸은 얇게만 줄이고 남겼다(SLA 숫자를 보이는 자리이고 시험이 이 칸을 본다).

## 시험
SCR-02·SCR-03 계열 38개 중 29개 통과. 실패 중 8개는 고정 시연 데이터가 없어 변경 전에도 실패하는 기준선(SCR-02-AC-3, SCR-03 7개). AC-11은 한 번 실제 Gemini 처리 지연으로 실패했고 다시 돌리니 통과했다.
