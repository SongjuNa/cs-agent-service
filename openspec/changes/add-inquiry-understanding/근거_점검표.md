## 3. 고친 것

| 지적 | 고친 내용 |
|---|---|
| L1 두 번 실패의 처리가 proposal·spec·design에서 서로 다름 | 세 문서를 하나로 맞췄다. 코드값 밖 응답이면 비우고 계속하고(FR-004 예외, FR-005 예외 1행), 시간 초과·오류면 FAILED다(FR-005 예외 2행, §2-2 T2). 문서끼리 다른 점은 결정 기록 C 항목에 남겼다 |
| 기준서 2장 표만 옮기면 CSV1-000017("Urgency: SITE_DOWN")이 SAFETY로 나오지 않음 | SAFETY 행에 K4 결정 문장을 넣었다. 통화 메모 행은 "위 기준과 다르면 위 기준을 따른다"로 바꿨다(구현 선택, 결정 기록 B) |
| seq 2 이후 요청의 긴급도를 버림(안전 놓침 위험) | 모든 요청 중 가장 높은 긴급도를 하위 문의에 쓴다(구현 선택) |
| L1 입력에 body_language가 들어 있었음 | language로 고쳤다(§3-1) |
| "제품 미확정"(FR-008 처리 4)이 빠짐 | spec·design·코드에 넣었다 |
| 펌웨어 "v3.4a"가 "3.4"로 통과할 수 있음 | 앞의 v·ver·version만 떼고, 나머지에 글자가 남으면 형식 확인으로 처리한다 |
| C-3 인용이 틀림 | 1순위 판 4장만 근거로 남겼다. AC-007-4의 4,000건 재현율은 키가 생긴 뒤 따로 하기로 했다 |
| AC-005-2가 저절로 통과하는 구조 | 시험이 gold.ticket_gold의 제목을 입력에 일부러 넣고, 그 제목이 버려지는지 본다 |
| AC-008-2의 "3.50" | 본문에 없다는 것을 시나리오에 적었다(결정 기록 C) |
| 시험 티켓 선택, 파일 나누기, 대조 방식, 제품군 다시 구하기, 동시 호출 수 미룸 | "구현 선택"으로 표시했다 |
| tasks 확인 기준 | 시간 초과 재시도를 넣고, 기준서와의 차이를 반영했다 |
| received_at, C-4 반품 시험, FR-005 예외 1행 연결, DB 저장 담당 | 범위 밖에 넣었다(저장 담당은 조장 확인) |
