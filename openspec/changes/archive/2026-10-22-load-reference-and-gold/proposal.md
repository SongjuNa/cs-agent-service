# Proposal: 기준정보·정답지 적재 (load-reference-and-gold)

## Why

뼈대에서 만든 DB는 표만 있고 내용이 비어 있다. 다음 변경인 규칙 엔진(FR-010~014)은 기준정보 표(ref)를 읽어야 하고, 규칙이 맞는지 확인하려면 정답지(gold)도 있어야 한다. 그래서 두 가지를 먼저 넣는다.

이 변경은 기능(FR)이 아니라 기술 명세서 v1.4 §9의 **W1 기준정보 적재**와 **W3 정답지 적재**다. 그래서 뼈대 때 정한 표기대로 요구사항 제목에는 (W1)·(W3)을, 시나리오 제목에는 W1-n·W3-n을 붙인다.

## What Changes

- **기준정보 적재 작업**: 운영진 데이터의 ref/ CSV 12개와 docs/doc_index.csv를 읽어 ref 스키마 24개 표에 넣는다.
  - 표 23개는 기술 명세서 §5-1, 여기에 문서 목록(document)이 더해진다.
  - 원본에서 바꾼 점(한 칸의 여러 값 펼치기, 'ALL' → 비어 있음 등)은 테이블 정의서 v1.3 §2-0을 그대로 따른다.
- **정답지 적재 작업**: tickets.csv(4,000건)와 resolution_cases.csv(800건)를 gold 스키마에 원본 열 이름 그대로, 모두 문자열로 넣는다(테이블 정의서 §3).
  - 입력 열만 보이는 뷰 `gold.v_inputs`는 뼈대에서 schema.sql이 이미 만들었다. 적재가 끝나면 이 뷰에 4,000행이 보인다.
- **다시 실행해도 같은 결과**: 적재 작업은 표를 비우고 처음부터 다시 넣는다(기술 명세서 §9 W1).
- **README**: 데이터를 놓을 위치와 적재 명령을 추가한다.

## Capabilities

### New Capabilities
- `reference-data`: 기준정보·규칙표(ref 스키마)를 운영진 CSV에서 채우는 동작.
- `gold-dataset`: 운영진 정답지(gold 스키마)를 원본 그대로 채우는 동작.

### Modified Capabilities
- 없음.

## 범위 밖

- 문서 청크(doc_chunk)와 임베딩: W2, 6번 변경 `add-evidence-lookup`에서 한다.
- 고장 사전 증상 벡터(기술 명세서 §9 W1에 포함): 고장 진단 FR-018이 3순위라서 이번에 만들지 않는다. 임베딩 모델 호출도 필요하다.
- **"우선순위 규칙·SLA 목표·필수정보를 4,000건에서 100% 재현"(W1 완료 확인)**: 이것을 확인하려면 규칙을 실제로 적용하는 코드가 필요하다. 그래서 3번 변경 `add-rule-engine`의 시험(FR-011·013·014)에서 확인한다. 이번에는 표마다 행 수가 테이블 정의서와 같은지, 그리고 외래 키 위반 없이 들어가는지를 확인한다.
- 팀 정답지(W9), 채점 제외 목록(W8), 설정 파일(W10): 1순위 구조 판 4장에 따라 이번에 만들지 않는다.
- 운영진 데이터 파일 자체: 저장소에 넣지 않는다(CLAUDE.md 규칙 8).

## Impact

- 새 파일: `jobs/load_reference.py`, `jobs/load_gold.py`, `backend/tests/test_data_load.py`.
- 고치는 파일: `README.md`(데이터 위치, 적재 명령), `.env.example`(데이터 폴더 위치 변수 1개).
- DB 구조(`docs/database/schema.sql`)는 고치지 않는다.
- 근거: 기술 명세서 v1.4 §5-1, §6-1, §9(W1·W3); 테이블 정의서 v1.3 §2, §3; 프로젝트 구조 1순위 판 2장(jobs/)·6장(2번 변경).
