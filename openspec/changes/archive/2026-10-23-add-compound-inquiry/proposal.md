# Proposal: 복합 문의 분리와 답변 구성 (add-compound-inquiry)

## Why

본문에 서로 다른 요청이 둘 이상 있으면 요청마다 하위 문의로 나누고, 하위 문의마다 처리 흐름을 따로 돌려야 한다(근거: 명세서 v1.5 FR-006 기능 설명, D16). 답변이 준비된 하위 문의부터 메일을 만들고 메일 끝에 모든 하위 문의의 상태 목록을 붙여야 한다(근거: FR-022 기능 설명, D15). 1순위는 하위 문의 1개만 만들고 나머지 요청은 "복합 문의 가능(FR-006, 2순위)" 표시만 했다(근거: 이 변경 전 `app/llm/understand.py` FLAG_MULTI_REQUEST, config.yaml "1순위는 하위 문의 1개").

## What Changes

- **나누기 (FR-006)**: 분류 호출(L1)이 돌려준 요청을 같은 유형끼리 합친 뒤 요청마다 하위 문의(seq 1..n, 본문 순서)를 만든다. n ≥ 2이면 ticket.multi_yn을 켜고 sub_ticket 행 `{ticket_id}-{seq}`를 더 만든다(근거: FR-006 처리 1~5, 기술 명세서 v1.4 §2-3 sub_ticket_id, schema.sql ticket.multi_yn).
  - 하위 문의마다 자기 유형·근거 문장·긴급도로 추출·규칙·근거·초안을 돈다(근거: FR-006 처리 4, §2-1 하위 문의 그래프).
  - 막는 정보가 있는 하위 문의만 정보 요청으로, 나머지는 근거 검색과 답변으로 간다(근거: §2-5 분기③, FR-022 처리 2).
  - 티켓의 유형은 하위 문의 유형을 순번 순으로 ';'로 이어 상세 응답에 보인다(근거: FR-006 출력 "category_code(';' 구분 문자열)", 기술 명세서 §3-2 "티켓에 ';'로 이은 문자열은 두지 않는다 … 조회 시 string_agg로 이어 붙인다").
- **답변 메일 구성 (FR-022, T5)**: 복합 문의에서 답변 초안(L4 단락 모드)이 생긴 하위 문의마다 메일 한 통을 만든다: 인사말(L5) → 단락 → 문의 상태 목록(부록 A-2 S-1~S-6) → 맺음말(L5). L5가 실패하면 고정 문구 F-2(근거: FR-022 처리 1·3·4, 에이전트 설계서 4-6 모드, 4-7 L5, 부록 A-2·A-3, §2-2 T5).
  - 상태 목록은 하위 문의마다 한 줄이고 예상 완료 시각·SLA 목표 시간을 넣지 않는다(근거: FR-022 처리 3, AC-022-4).
  - 근거가 없어 초안이 없거나 처리가 실패한 하위 문의는 "담당자 확인 중"(S-6) 줄로 나타난다(근거: FR-022 처리 7, 예외 3행, AC-022-3).
  - 메일마다 자체 대조를 하고, 상태 목록 줄 수가 하위 문의 수보다 적으면 "상태 목록 누락"을 표시한다(근거: FR-022 처리 5, 예외 1행, 에이전트 설계서 6-1 3번).
  - 메일은 그 하위 문의의 FINAL_REPLY DRAFT 한 행이다. 발송하면 그 하위 문의만 RESOLVED(근거: FR-022 처리 6, AC-022-2, 이 변경 전 `send_draft` 전이).
- **실행 기록 (FR-036 AC-036-4)**: 복합 문의는 티켓 run(sub_ticket_id 없음)에 T2·T5·T6을, 하위 문의마다 run을 따로 두어 Q 단계를 남긴다(근거: AC-036-4, §6-5, 테이블 정의서 v1.3 agent_run.ticket_id "티켓 그래프 실행은 sub_ticket_id가 없어서 둔다", 기술 명세서 §6-2 agent_run 행).

## Capabilities

### New Capabilities
- `compound-inquiry`: 복합 문의 분리, 하위 문의별 처리, 답변 메일 구성.

## 범위 밖

- **팀 정답지 채점(AC-006-4, AC-022-5)**: 팀 정답지(W9) 적재가 정해지지 않았다. 1순위의 같은 종류 AC와 같이 범위 밖으로 둔다(근거: 개발_결정_기록 C-3, 기술 명세서 §10).
- **같은 부서 하위 문의를 한 메일에 묶기**: FR-022 처리 1은 "묶을 수 있다"이다. 이 변경은 하위 문의마다 한 통으로 만든다(근거: FR-022 처리 1, 구현 선택).
- **동시 실행(T3 병렬)과 하위 문의 120초 상한**: 하위 문의를 순번 순으로 차례로 처리하고 한 하위 문의의 실패는 그 문의에만 표시한다. 데이터에서 한 문의의 요청은 최대 2개다(근거: §2-4 "데이터에서는 한 문의에 최대 2개", C-90).
- **코드값 밖 유형을 그 하위 문의만 다시 묻기**: 분류 호출은 응답 전체를 스키마로 검사하므로 한 요청만 다시 물을 수 없다. 응답 전체를 1회 다시 부른다(1순위 그대로)(근거: FR-006 예외 2행, 기술 명세서 §3-2, C-91).
- **상태 목록의 14개 언어 문안**: 영어 원문(부록 A-2)만 두고 다른 언어 메일에도 영어 줄을 붙인다(근거: 에이전트 설계서 T40, C-92).
- **화면(상세 하위 문의 구역, 접수함 "복합 n건 중 k")**: 18·19번 변경(근거: 기술 명세서 §11 006행, 변경 순서).
