# Spec Delta: ticket-detail

## MODIFIED Requirements

### Requirement: 접수와 처리 결과를 저장한다 (FR-038)
접수 API는 미등록 고객을 거부하고, 티켓·하위 문의·INQUIRY 메시지(원문, 가린 곳 수)·접수 이력을 한 트랜잭션으로 저장한 뒤 처리 흐름을 백그라운드로 돌려야 한다(MUST)(근거: 기술 명세서 v1.4 §2-4, §8-1 POST /tickets, 명세서 FR-038 처리 3). 처리가 끝나면 판단값, 초안(DRAFT), 대역, 자체 검사, 실행 기록을 저장해야 하며, 실행 기록에는 가린 글만 넣어야 한다(MUST)(근거: §6-2, §7). 초안은 DRAFT로만 저장해야 하고, 초안을 만든다고 상태가 바뀌어서는 안 된다(MUST)(근거: CLAUDE.md 규칙 3, 명세서 AC-015-4). 처리 흐름이 끝나면 NEW → IN_PROGRESS로 바꾼다(근거: 기술 명세서 §2-2 T6, 명세서 FR-001 처리 4, 개발_결정_기록 C-51). 이 저장은 FR-031 화면의 선행 작업이다.

#### Scenario: AC-015-4 초안은 DRAFT로만 있고 상태는 그대로다
- **GIVEN** CSV1-000017을 접수해 정보 요청 초안이 만들어진 상태
- **WHEN** 발송 전 메시지 이력과 상태를 본다
- **THEN** 초안은 DRAFT 행으로만 있고 하위 문의 상태는 처리 흐름 종료로 바뀐 IN_PROGRESS다(이력 INTAKE, PIPELINE_DONE)

#### Scenario: AC-038-1 원문은 저장되고 실행 기록은 가려진다
- **GIVEN** 본문 "contact me at kim@example.com or +82-10-1234-5678"로 접수
- **WHEN** 저장된 INQUIRY 행과 실행 기록을 본다
- **THEN** INQUIRY 본문은 원문 그대로이고 mask_count는 2이며, 실행 기록에는 "kim@example.com"과 "1234-5678"이 없다

### Requirement: 초안을 임시 저장하고 승인·발송한다 (FR-031)
임시 저장은 DRAFT 본문만 바꾸고 대역을 다시 만들며 검증은 다시 부르지 않아야 한다(MUST)(근거: 명세서 FR-031 처리 7, FR-039 AC-039-4, 추가 결정 가3). 승인·발송은 상담원 ID와 본문을 확인해야 한다(MUST)(근거: 화면 정의서 v2 0-3, P7 오류 문구). 최종 본문의 자체 대조 불일치(답변은 인용·숫자, 정보 요청은 막는 항목 라벨)·검증 지적·남은 막는 항목이 있으면 확인을 받은 뒤에만 보내고 그 선택을 기록해야 한다(MUST)(근거: FR-031 처리 2, 예외 5행, FR-049 처리 5, 에이전트 설계서 6-1). 발송은 SENT 행을 새로 쓰고 초안을 APPROVED로 바꾸며 처음 발송이면 1차 응답 시각을 기록해야 한다(MUST)(근거: FR-031 처리 3·5). 같은 초안은 한 번만 보내야 한다(MUST)(근거: FR-031 예외 4행). 발송 뒤 상태 전이는 status-sla 요구를 따른다(근거: FR-031 처리 4, config.yaml "FR-031의 발송 뒤 상태 전이는 FR-025·026 변경에서 붙인다").

#### Scenario: AC-031-1 정보 요청 발송
- **GIVEN** CSV1-000017의 정보 요청 초안
- **WHEN** 승인·발송한다
- **THEN** INFO_REQUEST SENT 행이 생기고 1차 응답 시각이 발송 시각으로 기록되며 상태가 WAITING_CUSTOMER가 된다

#### Scenario: AC-031-2 고친 답변 발송
- **GIVEN** CSV1-000004 답변 초안에서 한 문장을 고친 경우
- **WHEN** 승인·발송한다
- **THEN** SENT 행의 수정 여부가 Y이고 원본 초안 행은 글자가 바뀌지 않은 채 APPROVED이며 상태가 RESOLVED가 된다

#### Scenario: AC-031-3 근거 밖 숫자
- **GIVEN** 답변 초안에 조회값에 없는 숫자를 써 넣은 경우
- **WHEN** 승인을 누른다
- **THEN** "근거 밖 숫자" 확인이 요구되고, 그래도 발송하면 발송되며 override_check가 기록된다

#### Scenario: AC-031-5 두 번 승인
- **GIVEN** 이미 발송한 초안
- **WHEN** 두 번째 승인 요청이 온다
- **THEN** 거부되고 SENT 행은 1건이다

#### Scenario: AC-039-2 발송 본문에 대역이 없다
- **GIVEN** CSV1-000004 프랑스어 답변 초안을 승인·발송한 뒤
- **WHEN** SENT 행을 본다
- **THEN** 본문은 프랑스어 초안뿐이고 대역 문장이 없다

#### Scenario: AC-039-4 임시 저장하면 새 대역
- **GIVEN** 상담원이 초안 한 문장을 고쳐 임시 저장한 경우
- **WHEN** 대역을 본다
- **THEN** 고친 문장이 반영된 새 대역이다
