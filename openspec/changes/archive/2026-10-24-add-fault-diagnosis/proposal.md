# Proposal: 고장 진단 (add-fault-diagnosis)

## Why

고장 계열 문의에서 상담원은 에러 코드나 증상으로 고장 사전을 직접 찾아야 원인과 조치, 현장 출동·교체 필요 여부를 안다. 시스템이 고장 사전(97건)에서 "진단 후보"를 찾아 상담원에게 참고 자료로 보여 주어야 한다(근거: 명세서 v1.5 FR-018 기능 설명). 진단 후보의 현장 출동·교체 필요 표시는 다음 변경의 이관 후보(FR-020)의 입력이다(근거: FR-018 처리 5, FR-020 입력). 지금은 진단 단계가 없고 티켓 상세에는 "3순위 기능이라 아직 없습니다"만 있다(근거: 이 변경 전 `frontend/src/DetailTabs.tsx`, 결정 기록 C-111).

## What Changes

- **고장 진단 단계 Q8a (FR-018)**: 규칙 단계(Q2~Q6) 바로 뒤, 정보 요청 여부와 상관없이 돈다. 유형이 DEFECT·INSTALL·WARRANTY인 하위 문의만 진단한다(근거: 기술 명세서 v1.4 §2-1 흐름, §2 "Q8a와 Q9a는 정보 요청 여부와 상관없이 규칙 단계 바로 뒤", §2-5 분기⑦, FR-018 처리 1).
  - 정확 조회: 에러 코드가 있으면 같은 제품군·같은 에러 코드의 고장 사전 행을 찾는다. 찾은 방법 EXACT, 점수 1.0(근거: FR-018 처리 2, §4-6 1번).
  - 증상 검색: 정확 조회가 없거나 에러 코드가 없으면 같은 제품군 행 중 증상 문장이 가까운 상위 3건. 찾은 방법 SYMPTOM. 다른 제품군은 뺀다(근거: FR-018 처리 3, §4-6 2번).
  - 출력: 후보마다 고장 사전 항목 식별자(fault_id), 원인, 점검, 조치, 현장 출동·교체 필요, 찾은 방법, 점수(근거: FR-018 처리 4·출력, §4-6 3번).
  - 예외 4개: 제품군 항목 없음 → 진단 없음 / 에러 코드 미등록 → 증상 검색 / 점수가 모두 기준 미만 → "관련성 낮음" / 검색 실패 → 진단 없음 "진단 실패", 흐름은 계속(근거: FR-018 예외 처리 표).
  - 저장: 상태 객체 fault_candidates와 실행 기록(agent_step.output_json, 단계 Q8a). 문서 근거(evidence_json)에는 넣지 않는다(근거: §4-6 4번, T42).
  - 답변 초안(L4) 입력에 넣지 않는다. 확인할 수 있게 L4에 넣은 항목 이름 목록을 실행 기록 Q10에 남긴다(근거: FR-018 처리 5, AC-018-4, 에이전트 설계서 v1.1 "넣지 않는 것 … 실행 기록의 넣은 항목 이름 목록으로 확인").
- **증상 벡터 보관**: 고장 사전 증상 문장 벡터는 새 열 없이 파일 캐시(Git에 올리지 않음)와 서버 메모리에 둔다(근거: 조장 결정 2026-10-23, openspec/config.yaml, CLAUDE.md 규칙 4·8).
- **티켓 상세 표시**: 고장 계열 문의 구역에 "고장 진단 후보"(1순위 크게, 2·3순위 접힘, "참고용, 초안에는 쓰지 않음", "관련성 낮음")와 근거 줄 "고장 진단"(없으면 "없음(사유)")을 보인다(근거: 화면 정의서 v1 SCR-03 C-08, FR-030 처리 2, FR-024 입력, AC-024-1).

## Capabilities

### New Capabilities
- `fault-diagnosis`: 고장 계열 하위 문의의 진단 후보(정확 조회·증상 검색)와 그 표시.

## 범위 밖

- **이관 후보(FR-020)**: 다음 변경 23 add-escalation-candidates(근거: 3순위_시작_전후비교.md §3 변경 순서, 조장 승인 2026-10-24 스레드 답변).
- **유사 해결사례 검색(FR-019)**: 여유 시 기능(근거: openspec/config.yaml, 기술 명세서 §4-7).
- **고장 사전의 DB 열·관리 화면**: 나중에 추가(근거: 조장 결정 2026-10-23, openspec/config.yaml).
- **팀 정답지 채점(AC-018-5)**: 팀 정답지 적재(W9)가 없어, 대신 tickets.csv로 정확 조회 재현 일치율을 보고한다(근거: 결정 기록 C-3 선례, 구현 선택 C-137).

## Impact

- 새 파일: `backend/app/retrieval/fault.py`(진단·벡터 캐시), `backend/app/pipeline/diagnose.py`(노드 일), 시험 `backend/tests/acceptance/test_fault_diagnosis.py`(근거: design 결정 1~5).
- 고치는 파일: `backend/app/pipeline/graph.py`·`state.py`·`runlog.py`(노드), `backend/app/db/store.py`(Q8a·Q10 기록), `backend/app/db/detail.py`(상세 응답), `backend/app/llm/drafts.py`(L4 입력 항목 이름), `frontend/src/DetailTabs.tsx`·`api.ts`, `.gitignore`, `docker-compose.yml`(캐시 볼륨)(근거: design 결정 1~5).
- DB 구조는 고치지 않는다(근거: CLAUDE.md 규칙 4, 조장 결정 2026-10-23).
