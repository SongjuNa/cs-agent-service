# Spec Delta: dept-reply

## Purpose

이관받은 부서 상담원이 C/S 팀에 회신을 등록하고, 예외 부서(FIELD_SVC, SALES_OPS) 상담원이 고객에게 직접 메일을 보내며, C/S 상담원이 그 회신을 티켓 상세에서 본다(명세서 v1.5 FR-033 처리 8·9, FR-031 처리 9, FR-030 처리 2).

## ADDED Requirements

### Requirement: 이관 부서 회신 등록 (FR-033 처리 8)
시스템은 ESCALATED인 하위 문의에서 이관받은 부서(escalated_to) 상담원의 회신만 받아 ESCALATION_NOTE RECEIVED(보낸 쪽 DEPT, 보낸 주체 = 그 상담원)로 남기고 상태를 DEPT_REPLY 전이로 IN_PROGRESS로 바꿔야 한다(MUST)(근거: FR-033 처리 8, 기술 명세서 v1.4 §8-1, §6-4). 회신은 메일이 아니며 고객에게 가지 않아야 하고 임시 저장은 없어야 한다(MUST)(근거: FR-033 처리 8). 본문이 비면 "내용을 입력하세요"로 거부해야 한다(MUST)(근거: FR-033 예외 표 4행).

#### Scenario: AC-033-3 QA_CLAIM 회신 등록
- **GIVEN** QA_CLAIM으로 이관되어 ESCALATED인 문의
- **WHEN** QA_CLAIM_AGENT_01이 QA_CLAIM 접수함에서 그 문의를 열어 회신을 쓰고 [회신 등록]을 누르면
- **THEN** IN_PROGRESS가 되고 ESCALATION_NOTE RECEIVED(보낸 쪽 DEPT, 보낸 주체 QA_CLAIM_AGENT_01) 행이 생기며, C/S 상담원의 티켓 상세 "부서 회신" 영역에 그 회신이 보인다

#### Scenario: 빈 회신
- **GIVEN** ESCALATED인 문의
- **WHEN** 본문 없이 [회신 등록]을 누르면
- **THEN** "내용을 입력하세요"로 거부되고 상태는 그대로다

### Requirement: 회신 뒤 다시 처리 (FR-033 처리 8, FR-021 처리 5)
회신이 등록되면 시스템은 그 하위 문의를 새 실행(trigger DEPT_REPLY)으로 다시 처리해 근거 후보가 있으면 답변 초안을 새로 만들고, 회신 본문을 답변 초안(L4) 입력에 넣으며 회신 속 숫자를 자체 대조(Q11) 허용 목록에 넣어야 한다(MUST)(근거: 기술 명세서 v1.4 §2-4 "이관 부서 회신" 행, §3-4 2번, FR-021 처리 2·5 가-6). 검증 에이전트(L8) 입력에도 회신 본문을 넣어야 한다(MUST)(근거: §2-2 Q14 행, §3-1 L8 행, 에이전트 설계서 v1.1 L8 입력). 언어 모델로 가는 회신 본문은 가린 글이어야 한다(MUST)(근거: CLAUDE.md 규칙 2).

#### Scenario: 회신 속 번호를 쓴 초안
- **GIVEN** RMA 번호가 든 부서 회신이 등록된 하위 문의
- **WHEN** 다시 처리가 끝나면
- **THEN** 새 답변 초안이 DRAFT로 생기고, L4 입력에 회신 본문이 있으며, 그 번호를 쓴 초안은 자체 대조에서 근거 밖 숫자로 걸리지 않는다

#### Scenario: 근거 후보가 없는 하위 문의
- **GIVEN** 부서 회신이 등록됐지만 문서 근거 후보가 없는 하위 문의
- **WHEN** 다시 처리가 끝나면
- **THEN** 답변 초안은 만들지 않고 "근거 없음 — 상담원 작성 필요"로 둔다

### Requirement: 예외 부서 고객 메일 (FR-033 처리 9, FR-031 처리 9)
시스템은 FIELD_SVC·SALES_OPS 상담원이 자기 부서로 이관된 하위 문의에서 고객 메일을 [임시 저장]·[승인]으로 보내게 해야 하고, 그 메일은 자체 대조(Q11)와 검증 에이전트(FR-049) 없이 FINAL_REPLY SENT(보낸 쪽 DEPT)로 기록하며 상태를 DEPT_MAIL_SENT 전이로 IN_PROGRESS로 바꿔야 한다(MUST)(근거: FR-033 처리 9, FR-031 처리 9, D34, 기술 명세서 v1.4 §8-1). 그 밖의 부서는 고객 메일을 만들 수 없어야 하고, 본문이 비면 "내용을 입력하세요"로 거부해야 한다(MUST)(근거: FR-033 처리 9, 예외 표 4행, §8-1 dept-mail 행).

#### Scenario: AC-033-6 FIELD_SVC 메일 승인
- **GIVEN** FIELD_SVC로 이관되어 ESCALATED인 CSV1-000017
- **WHEN** FIELD_SVC 상담원이 고객에게 보낼 메일을 쓰고 승인하면
- **THEN** 숫자 검사·검증 에이전트 없이 FINAL_REPLY SENT(보낸 쪽 DEPT) 행이 생기고 상태는 IN_PROGRESS가 된다

#### Scenario: AC-031-6 예외 부서 메일 발송 행
- **GIVEN** 이관받은 문의에서 FIELD_SVC 상담원이 쓴 고객 메일
- **WHEN** 승인하면
- **THEN** 숫자·인용 대조와 검증 에이전트 없이 FINAL_REPLY 발송 행(보낸 쪽 DEPT)이 생긴다

### Requirement: 부서별 작성 영역과 "부서 회신" 영역 (FR-033, FR-030 처리 2)
티켓 상세의 작성 영역은 고른 부서에 따라 달라야 한다: 담당 부서(C/S)는 지금과 같고, 이관받은 부서는 회신 작성란과 [회신 등록]만, 예외 부서는 고객 메일 작성란과 [임시 저장]·[승인]이 있어야 한다(MUST)(근거: 기술 명세서 v1.4 §8-2, FR-033 처리 9). C/S 상담원 화면의 이관된 하위 문의에는 "부서 회신" 영역(이관 부서, 사유, 이관 시각, 회신 본문, 작성 상담원, 회신 시각)이 있어야 하고, 회신이 없으면 "부서 회신 대기 중"을 보여야 한다(MUST)(근거: FR-030 처리 2).

#### Scenario: AC-033-7 RND_FW 상세 화면
- **GIVEN** RND_FW로 이관된 문의
- **WHEN** RND_FW_AGENT_01이 상세 화면을 열면
- **THEN** [임시 저장]·[승인] 버튼은 없고 회신 작성란과 [회신 등록]만 있다
