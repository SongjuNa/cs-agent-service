# Spec Delta: verification

## Purpose

시스템이 만든 초안마다 언어 모델이 한 번 더 읽어 코드 검사가 못 잡는 뜻의 문제 4가지를 찾고, 상담원에게 검토 표시 ⑤로 보일 결과를 만든다. 발송은 막지 않는다(명세서 v1.5 FR-049).

## ADDED Requirements

### Requirement: 초안마다 뜻의 문제 4가지를 찾는다 (FR-049)
검증 단계는 대역 뒤에 초안마다 언어 모델을 1회 불러 근거와 뜻이 다른 문장, 약속 표현, 질문과 다른 답, 한국어 대역 오역을 찾아야 한다(MUST)(근거: 명세서 FR-049 처리 1·2, 기술 명세서 v1.4 §2-1). 지적마다 항목, 해당 문장(quote), 이유를 남기고, quote가 초안이나 대역에 실제로 없으면 그 지적은 버려야 한다(MUST)(근거: FR-049 처리 3 "해당 문장", 기술 명세서 §3-2 L8 "quote가 초안 또는 대역에 실제로 있는지"). 대역이 없으면 대역 오역만 빼고 검증하고 대역을 보지 못했다고 남겨야 한다(MUST)(근거: FR-049 예외 3행, 에이전트 설계서 v1.1 4-10절). 지적이 하나라도 있으면 "⑤ 걸림: {항목}", 없으면 "⑤ 통과"여야 한다(MUST)(근거: FR-049 처리 4). 검증은 초안을 고치거나 막지 않아야 한다(MUST)(근거: FR-049 처리 5, 기술 명세서 §3-3).

#### Scenario: AC-049-1 근거에 없는 할인은 약속 표현으로 걸린다
- **GIVEN** CSV1-000004 견적 초안에 근거에 없는 "30% 할인" 문장이 있고 코드 검사는 통과한 상태
- **WHEN** 검증한다
- **THEN** ⑤가 "걸림: 약속 표현"이고 그 문장이 강조할 문장(quote)으로 남는다

#### Scenario: AC-049-5 뜻이 다른 대역은 대역 오역으로 걸린다
- **GIVEN** 초안과 뜻이 다른 한국어 대역(시험용으로 만든 것)
- **WHEN** 검증한다
- **THEN** ⑤가 "걸림: 대역 오역"이다

### Requirement: 검증이 실패해도 초안은 그대로 둔다 (FR-049 처리 6·7)
검증 호출은 30초 상한으로 시간 초과나 형식 오류면 1회 다시 시도하고, 그래도 실패하면 초안을 그대로 두고 결과를 통과로 보이지 않게 "⑤ 검증 못 함(실패)"과 오류 종류를 남겨야 한다(MUST)(근거: 명세서 FR-049 처리 6·7, 예외 2행).

#### Scenario: AC-049-4 두 번 시간 초과
- **GIVEN** 검증 호출이 두 번 모두 시간 초과
- **WHEN** 흐름이 끝난다(화면·승인 버튼은 9번 변경, 실행 로그는 2순위 FR-036)
- **THEN** 초안은 DRAFT로 남고, ⑤는 "검증 못 함(실패)"이며 검증 결과에 오류 종류 LLM_TIMEOUT이 남는다

### Requirement: 검증 입력은 가린 글이다 (FR-049 입력)
검증 호출에 들어가는 모든 글은 보내기 직전 개인정보 가리기를 거쳐야 한다(MUST)(근거: 명세서 FR-049 입력, FR-038, CLAUDE.md 규칙 2).

#### Scenario: AC-049-6 검증 입력에 이메일·전화번호가 없다
- **GIVEN** 고객 요청 문장과 초안에 이메일 주소와 전화번호가 있는 경우
- **WHEN** 검증 호출의 입력 기록을 본다
- **THEN** 가려지지 않은 이메일·전화번호가 없다
