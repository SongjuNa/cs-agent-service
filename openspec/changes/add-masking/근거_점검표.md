# add-masking 근거 점검표

작성 2026-10-22 · 상태: 조장 검토 전 (propose 승인용)

문서의 문장마다 `(근거: …)`를 붙였다. 아래는 그 근거를 원본과 대조한 결과다. 점검 스크립트(`scripts/check_sources.py`)와 `/check-sources` 명령은 아직 main에 없어, 같은 검사를 이번에는 손으로(1·2장) 하고, 초안을 모르는 새 Claude(검증 에이전트)가 뜻을 대조했다(5장).

## 3. 문서끼리 또는 문서와 데이터가 다른 곳 (조장 확인 필요)

1. **규격 번호 제외(design 결정 2 마지막 행)**
   - 기술 명세서 §7 제외 목록에는 "규격 번호"가 없다. 그런데 데이터 7건(CSV1-000341, 001148, 001191, 001747, 002841, 003032, 003421)의 "IEC 62271-200/100"은 숫자 8개 + `-`라서 규칙 (나)에 걸린다.
   - 제외하지 않으면 AC-038-3(4,000건 0곳)이 실패하고, LLM이 규격 번호를 못 봐 COMPLIANCE 문의 답변 근거가 사라진다.
   - 초안은 "규격 기관 이름(IEC, EN, UL, IEEE, ISO, ANSI, CSA, KS) 바로 뒤의 숫자 묶음"을 제외 목록에 더했다. 승인되면 기술 명세서 §7 제외 목록에 한 줄 추가를 따로 제안한다(문서 수정은 조장 승인 뒤).
2. **AC-038-7(연락처 원문 표시)은 1순위에서 확인할 곳이 없다**
   - 기술 명세서 §7 "확인"은 AC-038-7도 단위 테스트로 만들라고 한다. 그런데 시뮬레이터 접수(FR-001)는 2순위이고, 연락처 표시(ticket.contact_*)는 화면 정의서 v2 부록 B의 2순위 화면(SCR-03-L L-01)에만 있어 1순위 화면 SCR-03M에는 없다.
   - 초안은 "범위 밖"에 두었다. 1순위에서 어떻게 할지(연락처 열이 있는 것만 전제 / 2순위 화면 때 시험) 조장이 정해야 한다.
3. **명세서 그룹 6 "본문의 긴 숫자열은 모두 날짜"와 데이터가 다르다**
   - 본문에 규격 번호 `62271-200`·`62271-100`(날짜 아님) 13곳이 있다(검증 에이전트 재계산). 1번 사안과 같은 뿌리이며, 명세서 데이터 사실 문장도 고칠 대상이다(문서 수정은 조장 승인 뒤).
4. **AC-038-1·4의 일부는 뒤 변경에서 확인한다**
   - AC-038-1 "저장된 INQUIRY 본문과 상담원 화면에는 원문", AC-038-4 "답변 초안에"는 메시지 저장·초안이 생기는 뒤 변경(5·7번)의 일이다. 이번에는 함수 수준에서 확인하고, proposal "범위 밖"에 어느 변경이 이어받는지 적었다.

## 4. 기준 문서에 없어 Claude가 정한 것 (구현 선택)

기능이 아니라 코드를 어떻게 짤지의 선택이다. 결과 값에는 영향이 없다.

- 함수 이름 `mask_fields`, `prepare_llm_input`, 자료형 `LlmInput`, 예외 `MaskingError`, 상수 `CONTACT_FIELDS`(`mask_text` 이름과 반환 꼴은 §7이 정함).
- 검사 순서 "보호 → 가리기 → 복원"(제외 목록을 먼저 적용하라는 §7을 구현하는 방법).
- 날짜 뒤에 붙은 시각(`HH:MM:SS`)까지 보호, 금액 꼴 = 천 단위 쉼표, 전화 (나)의 여는 괄호 처리.
- 정규식 표준 라이브러리 `re`만 사용, 새 라이브러리 없음.
- 예외 보조 시험 1개(AC 아님).

## 5. 검증 에이전트 결과 (2026-10-22)

초안을 쓰지 않은 새 Claude가 기준 문서와 데이터만 보고 약 120문장을 대조했다.
- 근거 있음·뜻 같음 약 102
- 뜻이 다름 11
- 근거 표시 틀림 6
- 근거 없음 1

데이터 재계산(날짜 외 "숫자 8개 + 구분 기호" 묶음 = `62271-200` 17회, `62271-100` 5회, 그 밖 없음. 규칙 (가)(다)·이메일 꼴 0회)은 1·2장의 손 점검과 같았다.
