# masking Specification

## Purpose
새로 받는 글의 이메일·전화번호를 규칙으로 가려, LLM 입력과 실행 로그에는 가린 글만 들어가게 한다. 원문은 DB에 저장해 상담원 화면에 보인다(명세서 v1.5 FR-038, 기술 명세서 v1.4 §7, 가-7).

## Requirements

### Requirement: 이메일·전화번호를 규칙으로 가린다 (FR-038)
가리는 함수는 글 하나를 받아 이메일 주소 꼴을 `user***@***.masked`로, 전화번호 꼴을 `*******`로 바꾸고 바꾼 곳의 수를 함께 돌려줘야 한다(MUST)(근거: 명세서 FR-038 처리 2·출력, 기술 명세서 §7 검사식 표). 전화번호 꼴은 (가) `+`로 시작하고 숫자가 8개 이상인 묶음 (나) 숫자가 8개 이상이고 구분 기호(공백, `-`, `.`, 괄호)가 하나 이상 있는 묶음 (다) 구분 기호 없이 0으로 시작하는 숫자 10~11자리여야 한다(MUST)(근거: 기술 명세서 §7 검사식 표, 명세서 FR-038 처리 2 ①②). 가리기는 LLM을 쓰지 않는 규칙이어야 한다(MUST)(근거: 명세서 FR-038 처리 2, 기술 명세서 §7). 함수는 받은 원문을 바꾸지 않고 새 글을 돌려줘야 한다(MUST)(원문은 DB에만 저장한다는 명세서 FR-038 처리 3을 지키기 위한 구현 선택).

#### Scenario: AC-038-1 이메일과 국제 전화번호가 2곳 가려진다
- **GIVEN** 본문 "contact me at kim@example.com or +82-10-1234-5678"(근거: 명세서 AC-038-1)
- **WHEN** 가리는 함수로 LLM용 글을 만든다
- **THEN** 결과에 "kim@example.com"과 "1234-5678"이 없다
- **AND** 가린 곳 수가 2다
- **AND** 넣은 원문 문자열은 그대로다(원문 저장과 화면 표시는 메시지를 저장하는 뒤 변경에서 확인)

#### Scenario: AC-038-6 구분 기호 없는 휴대폰 번호만 가려지고 주문 번호는 그대로다
- **GIVEN** 본문에 "0501234567"과 "PO 4500123456"이 함께 있음(근거: 명세서 AC-038-6, 팀 정답지 GS-075)
- **WHEN** 가리는 함수로 LLM용 글을 만든다
- **THEN** "0501234567"은 `*******`로 바뀌고 "4500123456"은 그대로다
- **AND** 가린 곳 수가 1이다

### Requirement: 제외 목록과 이미 가려진 값은 건드리지 않는다 (FR-038)
가리기 전에 제외 목록을 먼저 적용해, 날짜 꼴, 영문이 섞인 토큰(제조번호·에러 코드), 펌웨어 버전 꼴, 금액·수량, (다)에 해당하지 않는 구분 기호 없는 숫자열(주문 번호)은 가리지 않아야 한다(MUST)(근거: 기술 명세서 §7 제외 목록, 명세서 FR-038 처리 2). 데이터에 이미 가려진 값(`user…@***.masked`, `COMPANY_…`, `…_AGENT_nn`, `**MASKED**`)은 바꾸지 않아야 한다(MUST)(근거: 명세서 FR-038 처리 1, 기술 명세서 §7 제외 목록).

#### Scenario: AC-038-2 날짜·주문 번호·제조번호는 그대로다
- **GIVEN** 본문 "delivery by 2025-10-28, PO 4500123456, S/N LVB-2024-00117"(근거: 명세서 AC-038-2)
- **WHEN** 가리는 함수로 LLM용 글을 만든다
- **THEN** 세 값이 모두 그대로 있고 가린 곳 수가 0이다

#### Scenario: AC-038-4 이미 가려진 고객사 이름은 바뀌지 않는다
- **GIVEN** 글에 "COMPANY_4975_0183", "user57705@***.masked", "TS_TRF_AGENT_09"가 있음(근거: 명세서 AC-038-4, FR-035 데이터 사실)
- **WHEN** 가리는 함수로 LLM용 글을 만든다
- **THEN** 세 값이 그대로 있고 가린 곳 수가 0이다(초안에 넣는 동작은 7번 변경에서 확인)

### Requirement: 운영진 데이터에는 가릴 곳이 없다 (FR-038)
운영진 데이터 4,000건의 본문(inquiry_body), 정보 요청 문안(info_request_message), 최종 답변(final_reply)을 모두 가리는 함수에 넣으면 가린 곳 수의 합이 0이어야 한다(MUST)(근거: 명세서 FR-038 처리 6·AC-038-3, FR-035 처리 6·데이터 사실 "본문의 긴 숫자열은 모두 날짜").

#### Scenario: AC-038-3 4,000건에서 가린 곳이 0이다
- **GIVEN** 정답지 적재(2번 변경)를 마친 gold.ticket_gold 4,000행(근거: 테이블 정의서 §3)
- **WHEN** 세 열의 글을 모두 가리는 함수에 넣어 가린 곳 수를 더한다
- **THEN** 합이 0이다
- **AND** 규격 번호가 든 CSV1-000341의 본문 "IEC 62271-200"과 CSV1-002841의 "IEC 62271-100"도 그대로다(tickets.csv에서 확인. 기준 문서 제외 목록에 없는 규격 번호 제외는 조장 확인 사안, design 결정 2)

### Requirement: LLM 입력은 입구 하나를 지난다 (FR-038)
LLM 호출 계층은 모든 호출(L1~L8)의 입력을 보내기 직전에 입구 함수 하나로 가려야 한다(MUST)(근거: 기술 명세서 §7 "위치 (1)", 명세서 FR-038 처리 4, CLAUDE.md 규칙 2). 입구는 입력 항목의 모든 글을 가린 결과, 가린 곳 수, 넣은 항목 이름 목록을 돌려줘야 한다(MUST)(근거: 기술 명세서 §7, §6-5 "입력 항목 이름 목록").

#### Scenario: AC-038-5 입구를 지난 입력에는 가려지지 않은 도메인과 연락처 원문이 없다
- **GIVEN** 입력 항목에 본문 "reply to lee@customer.co.kr, tel 010-9876-5432"와 고객 언어 "en"이 있음(근거: 명세서 AC-038-5. 예시 문장은 시험용으로 지은 값, 언어 코드는 FR-001 입력 표의 15개 중 하나)
- **WHEN** 입구 함수로 LLM 입력을 만든다
- **THEN** 결과의 모든 글에서 "@" 뒤가 "***.masked"뿐이고 "9876-5432"가 없다
- **AND** 가린 곳 수가 2, 항목 이름 목록이 ["body", "language"]다

### Requirement: 연락처 열은 LLM 입력에 넣지 않고, 검사 오류면 호출하지 않는다 (FR-038)
보낸 사람 연락처(contact_name, contact_email, contact_phone)가 입력에 있으면 입구가 거부해야 한다(MUST)(근거: 명세서 FR-038 처리 5·7, 기술 명세서 §7 "LLM 입력과 실행 로그에 넣지 않는다". "거부" 방식은 구현 선택). 고객사 대표 연락처(primary_contact_name, primary_contact_email, primary_contact_phone)도 같이 거부해야 한다(MUST)(근거: 에이전트 설계서 v1.1 4-2절 공통 규칙 7). 가리기 중 오류가 나면 LLM을 부르지 않고 오류 종류 VALIDATION으로 멈춰야 한다(MUST)(근거: 기술 명세서 §7 "검사 오류", §6-5 오류 종류).

#### Scenario: AC-038-5 연락처 항목이 든 입력은 거부된다
- **GIVEN** 입력 항목에 본문과 함께 contact_email "lee@customer.co.kr"이 있음(근거: 명세서 AC-038-5 "보낸 사람 연락처 원문이 없다", FR-038 처리 7)
- **WHEN** 입구 함수로 LLM 입력을 만든다
- **THEN** 입구가 오류 종류 VALIDATION으로 거부하고 결과를 만들지 않는다
